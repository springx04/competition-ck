==================================================
四、专门处理4条 mapping_suspected
==================================================

目的不是自动交换 clip，而是回答：

“是否存在足够强、独立且一致的证据证明当前官方文本更匹配同 video_id 的另一个 clip？”

对每个 mapping_suspected 样本同时使用以下证据：

A. Official ↔ WhisperX-ASR
B. Official ↔ CTC diagnostic ASR
C. WhisperX-ASR ↔ CTC-ASR
D. 同 video_id 全部 clip 的文本匹配矩阵
E. 全100条 global retrieval 排名
F. 不同相似度指标：
   - token F1
   - 1-WER
   - CER similarity
   - character similarity

禁止只依据单一相似度决定映射。

==================================================
五、增加“映射稳定性”判断
==================================================

对每个相关 video_id 分别构建多个相似度矩阵：

S_whisper_token
S_whisper_char
S_ctc_token
S_ctc_char

分别运行 Hungarian matching。

比较不同矩阵得到的 permutation。

定义候选证据等级：

MAPPING_STRONG：
- 多种独立矩阵支持同一个 off-diagonal 映射；
- WhisperX 与 CTC-ASR 都支持；
- 原 diagonal 明显弱于候选；
- global retrieval 不产生明显矛盾。

MAPPING_WEAK：
- 存在 off-diagonal 优势；
- 但不同指标 / ASR 给出的最佳映射不完全一致。

MAPPING_UNRESOLVED：
- 各种匹配结果不稳定；
- 或所有绝对文本相似度都较低。

==================================================
七、视觉 Stage 3 的核心修改：TalkNet 只负责“锁定目标身份”
==================================================

当前问题：

部分视频中人物身份已经可以通过 ArcFace 连续追踪，
但 TalkNet 在静音、停顿、低语音活动窗口没有唯一 active identity，
导致这些时间全部被 mask。

这对于情感视觉特征过于保守。

新的职责：

ArcFace：
- 判断是不是同一个人；
- 负责 identity continuity。

TalkNet：
- 提供 active-speaker anchor；
- 用于确认哪个 ArcFace identity 是目标说话者。

AV-sync：
- 继续只作为辅助证据；
- 不作为硬否决条件。

==================================================
八、建立 TalkNet speaker anchor
==================================================

沿用 Stage 2：

window = 0.5 s
stride = 0.25 s

TalkNet logit >= 0 作为 active evidence。

但不要单窗口就永久锁定人物。

对每个 identity cluster：

统计：

positive_window_count
positive_duration
median_positive_logit
max_logit
positive_window_fraction

建立 speaker anchor。

主规则固定：

若某一连续时间段内：

1. 同一 identity cluster 至少有连续/邻近的 TalkNet positive windows；
2. 没有另一个 identity cluster 同时形成同等级 active evidence；

则该 identity 可以成为该连续视觉轨迹段的：

target_identity_anchor

不要根据本数据搜索最优 logit 阈值；
仍使用官方约定 logit >= 0。

==================================================
九、ArcFace身份连续传播
==================================================

这是 Stage 3 的重点。

当某 identity 已被 TalkNet 锁定为 target_identity 后：

即使后续某些窗口：

TalkNet < 0
或
没有有效语音活动，

只要满足：

1. ArcFace identity 仍是同一个 target identity；
2. OpenFace轨迹时间连续；
3. 当前窗口没有身份跳转；
4. 没有另一个身份出现明确 TalkNet active evidence；
5. 当前目标脸仍具有有效 OpenFace 特征；

则允许视觉身份沿轨迹传播：

TalkNet anchor
→ ArcFace identity continuity
→ silent / pause visual window 保留

不要要求每一个视觉窗口都必须“正在发声”。

==================================================
十、严格限制传播，避免错误身份扩散
==================================================

遇到以下任一情况立即停止传播：

- target identity 不再可见；
- ArcFace identity 发生跳变；
- 出现新的 identity 且 TalkNet 明确支持其为 active speaker；
- identity clustering 本身不稳定；
- OpenFace confidence / success 无法满足原有效性要求；
- 出现长时间轨迹断裂；
- no-face。

轨迹断裂传播主参数固定：

max_identity_gap = 1.0 s

只做敏感性分析：

0.5 s
1.0 s
1.5 s

主结果固定使用 1.0 s，
禁止选择“coverage最高”的参数。

==================================================
十一、多人物同时出现时保持保守
==================================================

如果窗口中：

- 多个 identity 同时可见；
- TalkNet 无法唯一确定 active identity；
- 且没有可以从前后 speaker anchor 连续推断的稳定目标身份；

则：

visual_status = ambiguous
vision_mask = 0

不得使用：

- 最大脸；
- 最中心脸；
- 最长track；
- face_id最小；
- confidence最高；

作为唯一目标人物选择依据。

==================================================
十五、重新定义最终“异常状态”
==================================================

当前报告不要再把以下全部统称为 unresolved：

CONFLICT
MISSING
PARTIAL
UNRESOLVED

它们语义不同。

最终增加：

resolution_status：

RESOLVED_VALID
RESOLVED_PARTIAL
RESOLVED_CONFLICT
RESOLVED_MISSING
UNRESOLVED

解释：

RESOLVED_VALID：
证据足够，正常使用。

RESOLVED_PARTIAL：
部分时间/模态可靠，按mask使用。

RESOLVED_CONFLICT：
已经有充分证据确认跨模态语义冲突，
处理方案明确为安全mask。
这不是“算法没解决”。

RESOLVED_MISSING：
明确真实缺失，例如 no_face。
处理方案明确为missing/mask。
这也不是“算法没解决”。

UNRESOLVED：
证据之间仍然冲突，
无法确定应该使用还是mask。
