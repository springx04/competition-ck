# Q2 数据处理审计与可执行候选

本记录只使用附件 2 `aligned_50.pkl` 的 train/valid/test 结构统计和现有 Q2
代码/报告，不引入外部数据集，不把 test 结果用于调参。新增采样函数
`q2.sampling.video_sample_weights` 只接收训练集 `video_id`，不读取标签、特征或
其他划分。

## 已核实的数据现象

- 三划分样本数为 train/valid/test = 3395/728/727；ID 和 video ID 均无跨划分
  重叠。
- `text_bert` 的 tokenizer、attention 和 token type 轴可重建；CLS、SEP、padding
  行的音频/视觉特征均为零。现有核查未发现可据此支持整体平移的证据。
- 音频行级有效掩码没有内部空洞，且只在文本内容范围内出现；视觉存在少量
  内部零行。原生全零视觉样本为 train/valid/test = 110/15/28，音频没有全零
  样本。零值承担当前不可观测状态，不能先均值填充后再用非零判定可用性。
- 原生视觉全零的类别比例在 train 中为 Negative/Neutral/Positive =
  1.76%/5.01%/3.29%，valid 为 1.46%/3.26%/1.78%，test 为 2.42%/7.59%/3.04%。
  视觉缺失可能与标签分布有关（Neutral 的比例在这三个划分都较高），但样本数很小，
  不能据此删除、填补或把缺失当作标签规则；保留显式可用性状态更稳妥。
- train 内有重复文本且部分标签冲突，视频内也有多片段和多标签。重复文本不能
  作为去重依据；当前视频隔离划分应保留。
- 逐维标准化只使用 train 的非零行，并把不可用行恢复为零，符合信息边界。
  现有 z-score=3 裁剪候选没有改善验证结果；音频少数维度很稀疏，不能仅凭稀疏
  或数值范围删除。

## 文本缓存一致性

当前 `src/q2/text.py` 会把每个观测文本位置的 BERT `[CLS]` 表示加入该位置的
token 表示；服务器保留的 `text.py.pre_tune_20260924` 旧实现只保留逐 token
表示，没有这一步。当前 `.cache/text/train/features.npy` 的文件时间早于这次代码
变更；用当前代码对 train 前两条样本实时重编码，与旧缓存比较得到绝对误差最大
4.7066、平均 0.3942，57% 的元素差异超过 `1e-6`（第 1 条样本的特征范数分别为
151.42 和 86.13）。因此冻结文本路径不能把旧缓存默认为当前编码语义：涉及冻结
模型的后续实验必须重建 train/valid cache，或显式恢复旧编码实现并把它作为独立
profile。端到端微调路径实时编码，需保持自己的 checkpoint 与缓存路径边界。

## 采样候选

train 中有 1528 个视频对应 3395 个片段，837 个视频含多个片段，最多 14 个。
因此新增 `video_sample_weights(video_ids, power)`，每个片段的权重为其视频片段
数的 `-power` 次幂。默认 `power=0` 与原普通 shuffle 等价；`power=0.5` 让长视频
仍保留全部片段，但降低其总抽样权重；`power=1` 才是视频级总权重完全相等，建议
先将 0.5 作为温和对照。WeightedRandomSampler 应只用 train metadata 的
`video_id`，保持每 epoch 与原 train 样本数相同且允许有放回抽样。

在 train 标签上的事后诊断（不用于拟合权重）显示，power=0 的期望抽样类别比例
为 28.48%/22.33%/49.19%，power=0.5 会变为 26.73%/22.21%/51.05%。这说明按
视频计数平衡并不等价于类别平衡，且会轻微提高 Positive 的抽样比例；它只能作为
视频重复度的独立候选，不能同时宣称解决类别不均衡。

该候选改变的是训练抽样分布，不改变标签、输入特征、valid 固定网格或 test 留出
规则。必须与普通 shuffle 固定 seed 对照，报告 clean/missing Macro-F1、每类 F1
和跨 seed 波动；若无稳定改善则弃用。
