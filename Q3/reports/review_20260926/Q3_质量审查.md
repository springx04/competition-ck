## 2. 优先修复的问题

### P1：随机对照没有实现方案规定的同几何、同粒度比较

实际入口是 `src/q3/__main__.py:125-147` 的随机起点拒绝采样，而非 README 所称的精确计数流程。它检查重叠，却允许两段相邻，合并后的片段数/长度会变；word 对照仍按普通位置抽取，能够切开整词。

本轮在附件4的 **14,114 个随机删除集合中发现 3,229 个（22.88%）实际连续段长度多重集合与目标不一致**。例：01号 `key.T.p10.point` 的目标为两段长度 `[1,1]`，随机编号9却是一个长度2的连续段。

在 **959 个整词随机对照中，577 个（60.17%）只删除某个词的部分已存储词元**。因此现有“整词 vs 随机”不是相同粒度的公平比较。不能把现有 G 和置信区间直接作为严格对照结论写进论文。

应按原有方案的规范片段与完整单元生成对照，保持实际三路成本及片段长度多重集合；报告可行集合数量、实际抽样数及不可用原因。修正后必须重新推理受影响的随机视图并重算统计。已有点归因和原预测可保留复用，不需要重训。

### P1：方向标签缺少整段重测后的判定，双头分歧字段恒为空

`__main__.py:95-99` 根据单点代理分数生成 support/suppress；`181-189` 重测后没有根据符号标记 direction_retained。候选身份可以保留，但不能直接当作有效支持/抑制证据。

|---|---|---:|---:|---|
| 09 | suppress.T.p20.point | +0.08936483 | +0.08936512 | 删除后原类别概率降低，不是有效抑制证据 |
| 18 | suppress.T.p20.point | +0.07869059 | +0.07869053 | 同上 |

20条共118个已重测方向候选，其中上述2个反转。这不是舍入误差。应保留失败候选并明确展示失败，不为了表面通过而删除记录或重新挑预算。主流程也尚未生成方案规定的方向匹配随机对照。

14号的分类影响首位是 **V**，回归强度影响首位是 **T**；CSV/JSON 的 `head_top_disagreement` 却始终为空（`__main__.py:264` 写死为 None）。这正是应展示的有价值案例。

### P1：题目要求的素材证据和可视化没有真正交付

题目明确要求典型解释卡、主要模态内局部重要性分布、三模态差异比较，以及可对应至原文/语音时段/视觉关键帧的证据。

- `map` 子命令未实现映射，只走 no-op（`__main__.py:271-286`）；`mapping.py` 只有 unresolved 占位函数。
- `report.py:15` 仅将整份 JSON 转义后塞入 HTML `<pre>`；`plots.py` 返回 None。20个 HTML 文件不等于20张可读解释卡，也没有题目要求的热图/局部重要性分布图。
- 正式 CSV 仅提供特征位置区间；案例未连接选中词元、原文字符和词时。完整转写的 CTC 列表与证据区间并排存放，不构成完成的连接关系。
- 479个词时记录全部 pending；465个 algorithm accepted、14个 rejected。算法接受不是人工确认。
- 19条的主模态是文本，可优先用本轮已核验的字符对应完成可读原文证据；14号主模态是视觉，其素材来源仍 unresolved，不能改成文本主模态以规避这一缺口。
- 审核 CSV 的人工修正没有被 report 读取；当前 report 直接读原始 `words.jsonl`。即使填完人工表，也不会自动进入输出。

本地20个对齐版视频均已存在。缺口不是“用户还需上传视频”。当前本轮没有进行音频听审；需将机器结构检查与听看核验分开记录。未知的官方 A/V 生成窗口不能仅靠目测相似或均匀分段升级为 verified。

独立复核还确认：20个对齐视频都有音视频轨道，CTC记录的区间正值、顺序、不重叠和视频时长边界检查通过；这只能排除结构性异常，不能证明词说在正确时间。14个算法拒绝词集中于06号2词、15号12词，应优先复核。02号 word_id=8、18号 word_id=3和12共3个原文空格分词项（标点/编码异常）没有词时记录，不能将479条解释为全部源词100%覆盖。媒体包含组合时间偏移与编辑列表，后续帧定位应使用实际 PTS/编辑偏移，不能用帧号除以假定帧率替代。

### P1：统计和实验验证不完整

- `summarize_stage`（`__main__.py:194-214`）按样本独立 bootstrap，没有使用 `video_id`。方案要求抽来源视频簇、带入簇内所有有效样本后取样本均值。独立样本区间不能标为视频簇区间。
- `statistics.cluster_bootstrap` 未被主流程调用；其实现对视频均值等权，也不等于方案规定的样本均值估计对象。仅接上函数名仍不足。
- 无随机集合的样本在汇总前被丢弃，`n_total` 和 `n_eligible` 一样，无法区分总样本、空模态、不可达预算与对照不足。
- 已计算 key 的 conditional/global keep，但随机集合只做 delete，没有等预算随机保留，也没有三路各自20%主证据并集的全输入保留对照。当前不能证明“选中证据具有相对充分性”。
- 实验行没有保存完整干预概率、强度和类别（`184-189`）；单凭 D、TV 无法补算所有干预后的 Accuracy/F1/MAE/Pearson。因此部分任务性能分析需补推理，而非仅改报告文字。
- valid 报告只有 G 表；缺少低影响/保留汇总、类别与错误分层、中性类诊断、模态整体影响与 Shapley 汇总、正式映射覆盖率。已存预测指标还缺 Weighted-F1、分类型指标和 Pearson，可从同口径 Q2 结果引用或补算。

### P2：分组敏感性只完成了部分形式，未完成规定的检验

`__main__.py:100-114` 的 block3/word 代理值是组内单点 D 的总和，没有对每组先做真实联合遮蔽扫描。选中组的最终并集虽被重测，仍不能替代整词/复制组扫描，也不能充分诊断多子词复制导致的稀释。

`select_units(... exact_cost=False)` 直接按代理值挑所有不超预算的方案，没有先固定最大可达成本。本轮最小反例：预算3；单元A成本2、分数10；单元B成本3、分数1。代码选成本2，尽管成本3可达。该反例证明实现偏离规定，不代表已量化全部真实样本受影响数。

还需补 A/V 有来源依据的复制组或明确不可用记录、分组与单点的同实际成本比较、集合 Jaccard。修正时保留未知 A/V 来源状态，不能凭相等向量直接宣称共享同一个真实时间窗口。

- `validate(final)` 主要数文件/行数，不能发现上述算法、方向、呈现或映射问题；其 complete 不应等同于题目完成。

- 根目录与 Q3 目录的报告、CSV、ZIP、valid 汇总均不相同；根目录报告没有整词实验，素材缺口还写模型待配置。应明确 Q3 目录为这轮审核使用版本，在下一轮统一发布位置。
- 本地 `Q3/runs/valid_main` 只有两个汇总文件，未同步728条逐样本归因/实验结果。现有历史 validation 和日志称已跑完，但本地不能独立重算 valid 全表。这是归档缺口，不等于断言服务器未计算。

## 3. 当前结果到底好不好

从保存的 valid 结果看，20%预算下文本/联合路径有值得保留的信号：文本 mean G=0.08530，正增益比例80.39%；联合 mean G=0.08596，正增益比例81.31%。音频 mean G=0.001685、视觉0.002605，绝对增益弱得多。以上是现有对照下的描述，**修正对照后才能判断效应大小和可靠性**。

专项19/20条主模态为文本、1条为视觉。不能因此说多模态解释“非常强”，也不能强行让每个模态一样重要。应解释真实依赖及其局限。原预测 valid Accuracy约61.5%、中性类 Q2 F1约0.401，也提示需保留失败案例，不能把能解释某次预测等同于预测正确。

本轮文本回溯显示：05号主文本证据为 `Hi / my / for`，16号为 `It / this`；09号包含 `) / not like / movie`。这些结果可能忠实反映模型对词元的依赖，却未必构成人类可理解的情感依据。解释卡应将“实际遮蔽片段”和展示上下文分开，并讨论功能词、标点及数据偏差，不为结果补写不存在的情绪原因。

因此当前评价是：**预测复现可靠；文本依赖有可用信号；严格忠实性评价需要修正；人可读性和素材可追溯性明显不足。** 没有证据支持直接称为“优质完成”，也没有理由因这些 Q3 实现缺陷推翻已经复现的 Q2 模型。
