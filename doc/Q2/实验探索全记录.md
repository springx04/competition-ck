## 读法与判定边界

- `valid M/C/MAE_m` 分别是固定 72 个主缺失场景等权平均 Macro-F1、clean Macro-F1、缺失场景 MAE；`test M/C` 同口径，主样本数分别为 728/727。详细 Accuracy、Weighted-F1、各类 F1、PCC 和逐场景表仍以对应源 CSV 为准。
- ledger 顶层 `independent_holdout=false`；38 条 evaluation 全部是 `split=test`，且发生在已经观察 test 的自适应探索流程中。题目第30段要求“train 学参数、valid 选结构/超参/阈值、test 只做最终推理”；因此这些 test 读数不仅不能当独立留出成绩，也不能据此声称遵守了题目的 valid-only 选模流程。`test` 列只写有源记录的数值；没有关联行时写“ledger 未关联 test 记录”，不推断“未运行”。
- 题目硬约束：附件2 train/valid/test 同一特征版本；附件3 仅无标签专项推理，不能训练、调参或计算准确率；分类需报告 Accuracy/F1，回归需报告 MAE/Pearson；核心代码、模型/配置/环境说明和附件3全量 CSV随交付；全附件 ≤50 MB且不能含身份信息。
- 当前实现书的正式部署规则仍是 valid 选出的单个变体 `seed=1111` 学生；三 seed 集成只能作为探索性补充，不能直接替代单学生 final selection。

## 现阶段可支持的结论

### 数值层面

- ledger 中单模型 test 读数最高的主缺失 Macro-F1 约为 0.5706（`attn_gridmix_reg1_v1`，seed 1111，带 valid 选择的类别偏置），最高 clean Macro-F1 约为 0.6052（`attn_cls_seed1113_v1` 的探索性偏置读数）；这些都不是独立留出成绩。
- [`joint_ensemble_corrected.json`](../../Q2/results/audit/joint_ensemble_corrected.json) 记录三份 `attn_gridmix_reg1` seed 的原始 logits 等权平均、只加一次 `[-0.1, 0.15, 0]` 的探索性集成：test 主缺失 Macro-F1 **0.573598**，clean Macro-F1 **0.608641**。这不是正式 selection，也没有本地导出/离线重载证据，且缺失均值仍低于项目优化记录中的 0.60 目标。
- “0.60”是当前优化方案的项目目标，不是题目正文规定的硬门槛；论文需把题目硬指标和项目内部目标分开写。

### 离线集成是否可作为最终 Q2 方案

从题目文字看，题目没有单独禁止集成模型；但按当前项目已经批准的实现边界，答案是：**该三模型离线集成目前只能作为探索性结果，不能直接作为最终交付方案。** 原因有四点：

1. [`E题_Q2_服务器具体实现说明_v1_Agent执行版.md`](E题_Q2_服务器具体实现说明_v1_Agent执行版.md) 固定最终部署为 valid 选出的单一变体 `seed=1111` 学生，并明确“不集成 3 个模型”；Q3 还要求复用同一个预测器和中间表示。
2. 三模型分别含微调 BERT。实现预算中单个 L4 BERT FP16 约 22.21 MB，三份仅约 66.6 MB，已经超过题目全附件 50 MB，还未计学生网络、代码、tokenizer、Q1/Q3材料；因此不能在未重做压缩、valid 重评和包体积验收的情况下提交。
3. 集成 test 读数来自已观察 test 后的自适应探索，audit 明确 `independent_holdout=false`。这同时偏离题目第30段规定的 valid-only 选模流程：不能在论文中称为独立留出泛化成绩，也不能把该 test 结果写成按题目流程完成的最终选模证据。
4. 当前本地证据树没有最终 `selection.json`、`outputs/q2_predictions_aligned.csv`、`delivery/q2_inference/`、`export_verification` 或 `package_sizes.csv`，所以不能声称集成已形成可离线重载交付包。

若最终仍想把集成作为候选，至少需要显式定义多模型推理接口、三份权重及包体积，使用 valid-only 规则冻结融合/偏置，再完成附件3 30行预测、离线新进程一致性和 Q3 同一模型接口验证，并把已见 test 历史写入限制；这属于改变当前 final 交付边界的方案。

## 交付前仍缺的证据

- 固定实现书要求的 10 variant × 3 seed、每个 60 轮、best 和完整 valid 结果，不能用这 67 条 exploratory ledger 自动替代；需要把 canonical suite 与探索候选分开。
- `reports/selection.json`：按 valid 规则选择单一 final variant、固定 seed=1111、best epoch 和 checkpoint。
- `outputs/q2_predictions_aligned.csv`：附件3 30条，至少包含 `sample_id,feature_version,pred_label,pred_score,prob_negative,prob_neutral,prob_positive`；同时保留状态分析，但不能把零行比例写成真实人工缺失率。
- `delivery/q2_inference/`：自足源码、学生权重、完整冻结文本模型、normalizer、许可证/来源说明和入口；关闭联网的新进程重载验证，valid 代表样本及附件3全量数值差异/类别一致性。
- `reports/package_sizes.csv` 与实际 Q2/全题 ≤50,000,000 bytes；不能用预估值冒充实测。
- `reports/report.md` 和 `reports/paper_q2_results.md`：正文需分别披露 valid 开发、test 探索/留出身份、附件3无真值专项；并覆盖缺失模态/位置/跨度、基础指标、消融、失败案例、资源和限制。
