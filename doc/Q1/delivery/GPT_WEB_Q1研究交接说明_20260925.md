## 2. 研究目标与固定边界

Q1 的目标是为后续建模生成可追溯的文本、音频和视觉特征，不是训练情感分类器。固定特征定义如下：

- 文本：BERT-base-uncased 最后一层，词级 768 维；
- 对齐：现有 CTC 词级时间定位；
- 音频：openSMILE eGeMAPSv02 LowLevelDescriptors，25 维；
- 视觉：OpenFace 2.2.0，22 维；
- 聚合：每条样本 50 个相对时间窗口；
- 显式保留 native source ID、CSR 映射、coverage、mask、status、reason 和 `paired_use`。

下一阶段不得更换上述特征定义，不重新训练情感模型，不使用情感标签影响审核，不删除自然缺失或未解决样本。优先目标不是提高覆盖率，而是保持：

```text
false_release =
人工确认不匹配、无可见目标、歧义或仍不可验证，
但最终 paired_use=true 的样本数
```

要求 `false_release=0`。

## 3. 已解决问题的方法

### 3.1 自动流水线与保守隔离

100 条样本均完成 `media → text → align → audio → vision → audit → pool`。每个模态保留样本行和失败/缺失原因，不因模态缺失删除样本。最终数组、mask、CSR、source ID、时间轴和 coverage union 均可复算。

对于 OpenFace 成功退出但零可用人脸的情况，新增 `vision_no_face` 审核项。该修正防止音文告警被释放后，无视觉证据的样本错误变为 `paired_use=true`。

### 3.2 双人独立审核设计

两位审核者独立审核全部 100 条样本，首轮不查看：

- 情感标签；
- 当前 `paired_use` 和自动告警；
- 辅助模型分数；
- 另一审核者结论。

总体音文类别为 `match/mismatch/unverifiable`；总体视觉类别为 `active_face_identified/no_visible_target/multiple_ambiguous/unverifiable`。原始一致率、Cohen’s κ 和 Krippendorff’s α 按 37 个 `video_id` 做 10,000 次分组 bootstrap。κ、α目标均不低于 0.80；不达标时修订规则并重审该类别全部样本。

### 3.3 多视觉片段和锚点词

原单行审核表不能表达跨镜头多个 episode，也无法可靠评价 temporal IoU，因此新增可变行数视觉片段表：

```text
sample_id,segment_id,start,end,visual_label,face_id,episode_id,confidence,evidence_note
```

锚点词表为：

```text
sample_id,word_id,raw_word,gold_start,gold_end,confidence,evidence_note
```

视觉校验包括媒体时长、真实 OpenFace 身份对、重复片段和同身份重叠。锚点校验包括真实 `word_id/raw_word`、每条最多 5 个、时间区间和不可验证证据。视觉端点相差超过 0.20 秒或 temporal IoU 小于 0.80 即进入裁决。

锚点子集固定为全部 23 条音文告警样本，加 10 条无告警对照。对照按现有 CTC 风险五分位各抽 2 条，固定种子 2026，优先不同原视频。每条按文本约 10%、30%、50%、70%、90% 位置预选 5 个词；实际为 33 条样本、165 个锚点词。

### 3.4 防止辅助模型污染金标准

两位审核者的六份提交先复制为只读快照并计算 SHA256。第三方裁决在看不到 TalkNet、ArcFace 和 WhisperX 输出的情况下完成。只有以下三个文件同时锁定 SHA256 后，辅助模型才解锁：

- 100 条最终总体决策；
- 最终视觉片段金标准；
- 最终锚点词金标准。

辅助模型只能用于后验评价和未来审核定位，不能自动生成 `confirmed_match` 或 `confirmed_mismatch`。

## 6. 辅助实验的冻结参数

- WhisperX：版本 3.8.6，`large-v2`，英文对齐模型 `WAV2VEC2_ASR_LARGE_LV60K_960H`；只做独立诊断。
- TalkNet：只接受官方 `pretrain_TalkSet.model`；官方输出是 class-1 logit，主阈值为 `logit >= 0`，不是概率 0.5。
- ArcFace：InsightFace `buffalo_l`，只做单样本内身份连接；主阈值余弦相似度 0.60，敏感性 0.50/0.70；使用前需确认非商业研究许可。
- 置信区间：按 37 个 `video_id` 分组 bootstrap 10,000 次，种子 2026。

不得依据本数据金标准选择最优阈值；冻结阈值只能做主分析，其他阈值只能作为敏感性分析。

## 7. 已知实现缺口，请重点审查

以下不是已确认 bug，而是希望网页版 GPT 重点检查的风险：

1. `segment_sets_equivalent` 使用贪心最大 IoU 匹配；多片段密集重叠时是否应改为匈牙利匹配？
2. 当前“同一 `face_id/episode_id` 片段不可重叠”是严格拒绝，是否需要允许有明确原因的重叠？如何结构化表达原因？
3. 总体视觉结论与最终片段只在金标准锁定时做一致性门禁；是否应在两位审核者提交阶段提前提示？
4. κ、α用于总体名义类别；多片段时间边界目前报告 agreement、tIoU 和端点差，没有对应的区间一致性统计。应增加哪些指标？
5. 当前音文评价器支持 CTC confusion、AUPRC、漏报和 `false_release`，但完整的视觉四组消融和锚点词起止误差评价器尚未实现。
6. 100 条样本、37 个视频可能导致置信区间较宽；如何报告小样本不确定性，避免把探索性结果写成确定结论？
7. 目前 49 条无告警样本全部进入人工复核，但锚点词只从其中抽 10 条。这个设计能否同时支持漏报审计和词时间误差估计？

## 8. 下一阶段必须遵守的顺序

```text
两位审核者独立完成三份表
→ 锁定六份原始提交及 SHA256
→ 计算总体类别与片段/锚点一致性
→ 若 κ 或 α < 0.80，修订规则并重审对应类别全部100条
→ 第三方盲裁决
→ 锁定 final_decisions、final_visual_segments、final_anchor_words
→ 解锁 TalkNet / ArcFace / WhisperX 辅助实验
→ 生成消融与误差报告
→ 生成 alignment_review.proposed.csv 和 target_face_segments.proposed.csv
→ 负责人逐行批准
→ vision --reuse-raw-csv → audit → pool → collect → validate → report
→ 验证 false_release=0
```

辅助模型失败不阻止人工审核和保守生产写回；只能将相应消融标为未完成。

## 9. 压缩包文件导航

- `reports/`：当前事实、历史结果、问题与实施进度；
- `configs/`：正式特征配置、审核实验配置和现有问题明细；
- `data_summaries/`：100 条样本的脱敏质量字段、自动问题、CTC 风险和审核进度；
- `core_code/`：审核、风险、评价、质量控制和流水线相关源码；
- `tests/`：与审核和安全隔离直接相关的测试；
- `metadata/`：版本、模型 revision、验证结果和文件校验清单。

压缩包不包含原始音视频、模型权重、Python/OpenFace 环境、特征大数组、绝对服务器连接信息或历史 8.6 GB 归档。没有原始媒体意味着网页版 GPT 可以审查方法与代码，但不能代替人工完成样本级视听确认。
