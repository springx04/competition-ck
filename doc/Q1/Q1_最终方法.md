# Q1 最终方法：可审计的文本–音频–视觉时间对齐与 50 窗口特征构建

> **文档定位**：本文件是 Q1 方法的唯一最终入口。内容以已经运行过的实现、配置和结果为准，不是此前的方案草稿。对应 Formal 运行为 `Q1/q1_features/runs/q1_full_20260924`，配置为 `Q1/q1_features/configs/q1.yaml`。Stage 1/2/3 的自动证据和候选修复均以只读、候选方式保留；Stage 4 只有冻结报告，没有新的最终 NPZ 或独立验收文件。

## 1. 任务边界和实现状态

Q1 的目标是把每个原始 MOSEI 视频样本转换为同一时间轴上的三模态特征：

\[
 X_i=\{X_i^{text},X_i^{audio},X_i^{vision}\},
 \quad X_i^{m}\in\mathbb{R}^{50\times d_m},
 \quad(d_{text},d_{audio},d_{vision})=(768,25,22).
\]

每个窗口都保留覆盖率、可观测性、扰动状态和源数据映射，因此下游可以区分“数值为零”和“该时间段没有可用观测”。本方法不训练分类器、不把标签用于特征提取，也不把 CTC 分数当作校准概率。Q1 当前生产包是**冻结特征提取结果**，不是一个已完成的情感预测模型。

生产批次的真实规模为 100 个样本、37 个源视频、7 个阶段；7 个阶段均为 100 成功、0 失败。最终处理状态为 49 个 `ok` 和 51 个 `partial`。这里的 `ok/partial` 是最终运行状态，不是单个提取器的进程退出状态：`ok` 还要求三种模态都至少有一个观测窗口并通过自动配对规则，`partial` 主要来自配对审计未决项，并非某个提取器崩溃。

这 51 条 `partial` 在 `reports/auto_resolution/problem_partition.csv` 中分为 `identity_only=28`、`text_audio_only_single_episode=10`、`identity_and_text_audio=9` 和 `vision_no_face_and_text_audio=4`。它们的 `pairing_status` 都是 `unverifiable`、`paired_use=false`；当前运行没有把任何一条未决记录改写成人工确认。逐条的 ID、有效时长、模态维度、粒度和配对状态见[全 100 条特征汇总](reports/全100条特征汇总.md)。

## 2. 输入、时间基准和输出契约

### 2.1 输入样本

`manifest.jsonl` 是样本主表。每行至少包含：

```text
sample_index, sample_id, video_id, clip_id, video_relpath,
raw_text, excel_sheet, excel_row, input_status
```

样本 ID 保持源数据的 `video_id$_$clip_id` 形式，不由文本或文件名重新推断。一个实际输入为：

```text
sample_id:    -3g5yACwYnA$_$13
video_id:     -3g5yACwYnA
clip_id:      13
video:        附件1-数据集原始多模态样本/MOSEI数据集部分原始视频-100条/-3g5yACwYnA/13.mp4
raw_text:     They've been able to find solutions or at least bring some answers to the table.
```

本批次另有 `labels.csv`，其标签分布为 Positive 57、Neutral 25、Negative 18；标签只被保留用于审计和后续实验，未参与 BERT、CTC、openSMILE 或 OpenFace 的输入，也未用于调参。

### 2.2 共同时间轴

对每个视频先读取容器和流信息，使用媒体时间戳计算持续时间 $D>0$。视频帧保留源帧索引和时间区间，目标采样频率为 25 Hz；音频转换为 16 kHz、单声道、浮点波形。所有中间记录都保存 `start_s`、`end_s` 或等价的源索引，避免只保存一个无法追溯的数值。

音频帧的时间来自 openSMILE 的帧区间；如果重采样 WAV 比媒体持续时间多出尾部帧，则裁剪到 $D$。生产批次已修复两条约 0.000037 s 和 0.000022 s 的尾部超界记录。视觉帧使用视频时间戳而不是数组位置作为主时间。文本词区间由 CTC 得到，不能因为缺少区间而按词数平均分配时间。

### 2.3 最终生产输出

`features/q1_compact50.npz` 的核心数组为：

| 数组 | 形状 | dtype | 含义 |
|---|---:|---|---|
| `text` | `(100,50,768)` | `float32` | 50 个公共窗口的 BERT 词级池化结果 |
| `audio` | `(100,50,25)` | `float32` | eGeMAPSv02 LLD 重叠加权结果 |
| `vision` | `(100,50,22)` | `float32` | AU、姿态和视线结果 |
| `valid_mask` | `(100,50)` | `uint8` | 窗口几何有效性；本批次正持续时间样本均为 1 |
| `observed_mask` | `(100,50,3)` | `uint8` | text/audio/vision 是否至少有合格源观测 |
| `perturb_mask` | `(100,50,3)` | `uint8` | 是否受人为扰动；生产批次全为 0 |
| `coverage` | `(100,50,3)` | `float32` | 各模态在窗口内的时间覆盖率 |
| `time_intervals` | `(100,50,2)` | `float64` | `[kD/50,(k+1)D/50)` |
| `duration` | `(100,)` | `float64` | 媒体持续时间 $D$ |
| `valid_length` | `(100,)` | `int64` | 有效窗口数 |
| `sample_index` | `(100,)` | `int64` | 与 manifest 对齐的行号 |
| `paired_use` | `(100,)` | `uint8/bool` | 配对审计后的下游使用标志 |

原生帧/词和窗口的映射保存在样本级 CSR 载荷中，至少包含 `indptr`、`source_ids`、`overlap_s`、`weights`。它与 `features/q1_compact50.npz` 的聚合数组是两个产物层级：前者位于运行归档的 `samples/*/map_{text,audio,vision}.npz`（并由 timeline/summary 引用），后者只保存 compact50 特征、mask、coverage、时间轴等数组。若本地精简副本没有 `samples/`，只能引用归档/服务器映射，不能声称 CSR 文件随 NPZ 一并存在。

## 3. 可复现流水线

正式执行顺序为：

```text
prepare → media → text → align → audio → vision → audit → pool → collect → validate → report
```

对应实现位于 `Q1/q1_features/src/q1_features/`；runner 逐样本写阶段状态，只有必需的媒体/文本/对齐/音频/视觉提取阶段完成且三模态各有至少一个观测才标为 `ok`，有正持续时间但审计或某模态不可用则标为 `partial`，没有有效媒体则为 `failed`。本批次 `audit` 与 `pool` 也均完成并通过验证，但它们是最终验收统计，不应与 `processing_status` 的必需阶段条件混为一谈。

| 阶段 | 实际工具/实现 | 关键固定参数 | 阶段输出 |
|---|---|---|---|
| prepare | Python manifest/标签读取 | `seed=2026`，保留源 ID | `manifest.jsonl`、输入报告 |
| media | FFmpeg/PyAV/OpenCV 路径的媒体解码 | 音频 16 kHz；视频 25 Hz | `duration`、音频/视频源时间区间 |
| text | `google-bert/bert-base-uncased`，本地 Transformers | 最后一层，冻结，chunk 内容 510，stride 382，word mean | 词级 768 维向量 |
| align | ESPnet Conformer CTC + `ctc_segmentation` | blank 0，最小 log score -5，窗口 8,000–100,000 | 词区间、CTC 分数、原因 |
| audio | openSMILE 2.5.1 | `eGeMAPSv02` / `LowLevelDescriptors`，25 维 | 帧级 25 维 LLD |
| vision | OpenFace 2.2.0 `FaceLandmarkVidMulti` | `-au_static -aus -pose -gaze -2Dfp`，置信度 ≥0.8 | 25 Hz 帧级 22 维 |
| audit | 自动质量规则 + 未决人工复核表 | WER > .65 或词对齐比例 < .80 触发审计 | `pairing_status`、`paired_use`、issue CSV |
| pool | 公共 50 窗口重采样 | `bins=50`，coverage=`union` | compact50 NPZ；样本级 CSR 映射单独归档 |
| validate/report | 数组形状、有限值、映射和统计检查 | `selected_only=false` | `validation.json`、summary、timeline |

正式批次命令和依赖环境见 [实验结果报告](reports/实验结果报告.md)。在 `Q1/q1_features` 目录、已安装本地包和已准备模型的同等环境中，入口为 `python -m q1_features run --config configs/q1.yaml --run-dir runs/q1_full_20260924 --resume`；首次建立运行目录需先执行 `python -m q1_features prepare --config configs/q1.yaml --run-dir runs/q1_full_20260924 --data-root <data-root>`。具体服务器参数和阶段日志以运行记录为准。

## 4. 文本表示与 CTC 词级对齐

### 4.1 BERT 词向量

对 `raw_text` 按 tokenizer 的规则拆为原始词，并用 `is_split_into_words=True` 保留词到 sub-token 的映射。`bert-base-uncased` 使用最后一层 hidden state，模型处于 `eval()`，不计算梯度，输出转为 `float32`。由于模型内容上限，最多 510 个内容 token；窗口间使用 382 个 token 的重叠。重叠片段中属于同一词的向量先按 sub-token 平均，再对同一个词在多个 chunk 中的向量平均。

对第 $j$ 个词、其 sub-token 集合 $S_j$，词向量为：

\[
 e_j=\frac{1}{|S_j|}\sum_{r\in S_j} h_r^{(L)},
\]

其中 $h_r^{(L)}$ 是 BERT 最后一层向量。这个结果只描述词内容，不声称该词在视频中的发生时间。

### 4.2 CTC 时间对齐

文本先按 CTC 模型的 tokenizer 规则归一化为大写 token；数字、无法表示的符号和不支持片段均记录原词、规范化词和原因。Conformer CTC 模型在本地以波形或模型要求的窗口计算 token 后验，`ctc_segmentation` 在 token 序列上求单调路径。一个候选词 $j$ 的时间为 `[s_j,e_j)`，其接受条件包括：

\[
e_j>s_j,\quad 0\le s_j<e_j\le D+\epsilon,
\quad \bar{\ell}_j\ge -5.0,
\]

并且没有以下致命原因：`invalid_interval`、`low_ctc_score`、`contains_unk`、`unsupported_text`、`nonmonotonic_alignment`、`overlap_alignment`。超出媒体末端的微小浮点误差被裁剪到 $D$；不通过条件的词保留在审计表中，但不为它猜测一个时间区间。

`diagnostic_wer` 是通过 CTC 解码得到的诊断量，阈值为 0.65；它用于发现文本–音频可疑配对，不是校准后的识别概率，也不等价于人工标注 WER。`score_min_mean_over_L=30`、`min_window_size=8000` 和 `max_window_size=100000` 是 CTC 窗口参数，不能与质量阈值混用。

## 5. 音频表示

openSMILE 2.5.1 在 16 kHz 单声道信号上运行 `eGeMAPSv02` 的 `LowLevelDescriptors` 层，输出 25 个固定列。列顺序由 `features/audio_feature_names.json` 冻结，开头为 `Loudness_sma3`、`alphaRatio_sma3`、`hammarbergIndex_sma3`、`slope0-500_sma3`、`slope500-1500_sma3`、`spectralFlux_sma3`、`mfcc1_sma3`–`mfcc4_sma3`，随后为基频、jitter、shimmer、HNR、相对共振峰频率/带宽/幅度等特征；论文使用时应直接读取该 JSON，避免手抄列名或改变顺序。

若源帧区间为 `[s_i,e_i)` 且 25 维向量有限、区间长度为正，则进入池化；否则该帧的状态写入原因并作为不可观测。音频连续性和媒体帧计数分别记录，不能因音频帧数正常就推断文本或视觉一定可用。

## 6. 视觉表示、人脸轨迹和缺失定义

OpenFace 命令使用 `FaceLandmarkVidMulti`，开启静态 AU、AU、姿态、视线和 2D landmarks。最终 22 列严格为：

```text
AU01_r, AU02_r, AU04_r, AU05_r, AU06_r, AU07_r, AU09_r,
AU10_r, AU12_r, AU14_r, AU15_r, AU17_r, AU20_r, AU23_r,
AU25_r, AU26_r, AU45_r, pose_Rx, pose_Ry, pose_Rz,
gaze_angle_x, gaze_angle_y
```

每个候选行必须同时满足 OpenFace 成功、`confidence >= 0.8`、22 维有限。候选按源帧排序形成 episode；当相邻帧间隔超过 0.2 s、bbox IoU 低于 0.1 且中心跳变超过画面尺寸的 0.25，或场景直方图 L1 距离超过 0.65 时切分 episode。只有一个 episode 且每个目标帧只有一个候选时可以自动采用；多 episode 或同帧多候选时，诊断行保留 `episode_id`，生产 `eligible` 行默认标为 `identity_unknown`，只有 `target_face_segments.csv` 的显式复核行才能选入，不擅自把不同人脸拼成一条轨迹。

失败原因具有明确含义：

| 原因 | 进入池化 | 含义 |
|---|---|---|
| `no_face` | 否 | 该帧没有可用人脸候选；视频任务成功不代表一定有人脸 |
| `identity_unknown` | 否/待审计 | 有多个候选或无法确定目标身份 |
| `low_confidence` | 否 | 置信度低于 0.8 |
| `invalid_output` | 否 | 输出缺列、非有限或区间非法 |
| `scene_break`/多 episode | 按规则保留候选，默认要求复核 | 轨迹连续性不足 |

当前批次识别出 4 条零脸样本：`-NFrJFQijFE$_$1`、`-NFrJFQijFE$_$2`、`-mJ2ud6oKI8$_$1`、`-ri04Z7vwnc$_$0`。这 4 条是自然视觉缺失，不能写成“OpenFace 程序失败”。

## 7. 公共 50 窗口池化、覆盖率和掩码

对媒体持续时间 $D$，定义公共窗口：

\[
 I_k=[a_k,b_k)=\left[\frac{kD}{50},\frac{(k+1)D}{50}\right),\quad k=0,\ldots,49.
\]

一个合格原生观测 $x_i$ 的区间为 `[s_i,e_i)`，它在窗口 $k$ 的重叠时长为：

\[
 o_{ik}=\max\left(0,\min(e_i,b_k)-\max(s_i,a_k)\right),
 \quad w_{ik}=\frac{o_{ik}}{\sum_{r:o_{rk}>0}o_{rk}}.
\]

只对 $o_{ik}>0$ 的观测求重叠加权平均：

\[
 z_k=\sum_i w_{ik}x_i,\qquad
 C_k=\frac{\left|\bigcup_i([s_i,e_i)\cap I_k)\right|}{b_k-a_k}.
\]

`coverage` 是区间并集长度除以窗口长度，不能用帧数简单代替；`observed=1` 只表示至少一个合格源观测，不表示 $C_k=1$。窗口的可使用性写为：

\[
 U_{k,m}=V_k\,O_{k,m}\,(1-P_{k,m}),
\]

其中 $V$ 为窗口几何有效性，$O$ 为观测掩码，$P$ 为扰动掩码。本生产批次 $P=0$，因此下游仍需使用 `observed_mask` 和 `coverage` 处理自然缺失。

视觉的 17–21 维为角度（`pose_Rx`、`pose_Ry`、`pose_Rz`、`gaze_angle_x`、`gaze_angle_y`），使用加权圆均值：

\[
 \theta_k=\operatorname{atan2}\left(\sum_iw_i\sin\theta_i,\sum_iw_i\cos\theta_i\right).
\]

若合成向量长度小于 $10^{-6}$，该视觉窗口置为不可观测，但保留候选覆盖率和源映射以供审计。每个窗口的 CSR 权重之和应为 1；`validation.json` 会重新计算观测窗口数和权重映射。

## 8. 质量审计与 `paired_use`

自动审计以样本为单位检查：

1. `diagnostic_wer > 0.65`；
2. `accepted_words / spoken_words < 0.80`；
3. 视觉多 episode、身份不确定和零脸；
4. 音视频时间覆盖或源帧异常；
5. 人工复核表中的 `confirmed_match`、`confirmed_mismatch` 或 `unresolved`。

无自动问题时写 `pairing_status=no_issue_detected` 并令 `paired_use=true`。有问题时，只有所有相关复核行都是 `confirmed_match` 且自动问题得到释放，才可恢复使用；`confirmed_mismatch` 或 `unresolved` 保持 `paired_use=false`。当前 51 条问题样本的 78 条人工证据复核记录全部是 `unresolved`，所以 `paired_use=false`。这表示“尚未证明可配对”，不表示已经证明错配。

文本时序策略由审计状态控制：完全隔离时使用 `quarantine_all`，局部问题时只丢弃与隔离区间相交的词。没有时间证据时不把整段文本均匀放入 50 个窗口。审计表、证据接触表和 reviewer A/B 表都保留盲法字段；目前 reviewer 表和 target segment 表为空或未决，不能声称完成了人工金标准。

### 9.2 一个可画的跨源窗口

### 9.3 输出和解释

### 11.1 Stage 2：语义配对拆分与官方文本强制对齐

## 12. 失败方案、原因和适用边界

### 12.1 早期文档中的 MMSA-FET 直接入口

早期方案试图把附件目录直接当作 MMSA-FET 的批量输入。实际附件是片段 MP4、独立文本和需要本地模型的异构数据，输入契约、时间戳和输出维度均不匹配，因此没有把该入口冒充为生产实现。当前 runner 采用逐样本 manifest、独立三模态提取和显式 CSR 映射；MMSA-FET 文档保留为历史定位。

### 12.2 把 OpenFace 进程成功当作“有人脸”

OpenFace 可以正常退出但整段没有合格检测。若只看进程状态，会把零脸样本写成视觉全零并误认为有效。该做法被废弃；现在要求逐帧候选、置信度和有限值检查，写出 `vision_no_face`/`no_face`，并保留 4 条零脸 ID。

### 12.3 对缺少时间的词均匀分配区间

按词数均分会制造看似完整但不可审计的文本覆盖，尤其在静音、重叠说话和识别错误处。当前只使用 CTC 单调区间；低分、未知 token、非单调和重叠词均保留失败原因，不生成猜测时间。

### 12.4 用单一视觉帧表代替轨迹和 episode

单行“目标人脸”表无法表达多 episode、场景切换和身份不确定。当前实现保留 `episode_id`、bbox/场景切分证据，并让多 episode 进入复核。现有人工 segment 表尚未填充，因此不能把自动单 episode 假设写成全数据金标准。

### 12.5 TalkNet、MFA 和 WhisperX 的替代对齐

早期 Formal/Stage-1 交接快照中曾记录 TalkNet 权重下载超时、WhisperX 仅完成环境导入检查；这属于历史状态，不能覆盖后续真实运行记录。当前 Stage 1/Stage 2 已使用官方 TalkNet checkpoint 完成推理（191 个 episode 中 165 个可推理、26 个因片段过短或无同步帧失败、阈值为 class-1 logit ≥ 0），Stage 2 已用 WhisperX 3.8.6 的 Wav2Vec2 强制对齐完成 100/100 条。MFA 仍因缺少可锁定 executable、英文声学模型和词典而跳过，生产 CTC 未替换。当前证据均为 candidate-only，不代表人工金标准或正式写回。

### 12.6 ArcFace 和 AV-sync Stage-1 候选实验

ArcFace 使用 `buffalo_l` 在 CPU fallback 上生成 episode 级候选相似度，AV-sync 生成 25 Hz 局部滞后和置换空分布。这些结果只写入 [`reports/auto_resolution/`](../../Q1/q1_features/runs/q1_full_20260924/reports/auto_resolution/)，[`q1_auto_resolution.yaml`](../../Q1/q1_features/configs/q1_auto_resolution.yaml) 明确 `candidate_only=true`、`production_write=false`；没有经过人工确认，不能改写 `paired_use` 或 compact50。

### 12.7 人工复核未完成

当前有 78 条未决 evidence review 行、165 个盲法 anchor 行、两个 reviewer 的 100 行总表和空的 segment 表。因为没有金标准，不报告 reviewer agreement、precision、recall、F1 或“已解决配对率”。论文应把它们作为审计设计和未完成限制，并报告自动规则的可复核统计。
