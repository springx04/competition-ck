## 1. 目标、依据与执行范围

Q1的完成不能只由“程序不报错”“有一个NPZ”或“有100行”决定。需要同时证明：100条原样本有完整对应关系；接受的特征来自正确素材、真实时间与指定提取器；缺失和错配被如实处理；实际计算可重复；题目要求的全量汇总和典型样本证据已经形成。

本文依据当前题目Q1及其论文要求：完整覆盖、时序可核验、方法合理性与可复现性、100条结果表、至少1个典型样本。Accuracy、情感分类F1、情感强度MAE和Pearson是Q2/Q3预测任务的指标，**不要求为Q1临时训练分类器来生成这些分数**。本方案中的“时间误差”仅针对有参考边界的词时间；“正确率”必须明确具体检查对象和参考来源。

配套文档：

- [服务器实施说明](E题_Q1_服务器具体实现说明_v1_Agent执行版.md)：模型、依赖、算法、CLI与文件结构。
- [v3方法稿](E题_Q1_多模态特征构建方法_v3_审核稿.md)：建模定义和Q1—Q2—Q3边界。
- [数据细节](E题数据细节.md)：既有数据统计，不替代本次结果检查。

服务器应取得前两份文档、实现代码、附件1原始数据、完整run目录和本地预训练模型。无需为本轮验收加载附件2巨型PKL，不读取附件3/4调参；其接口边界检查采用既有字段说明和本轮README即可。

固定的主方法仍为：BERT768、eGeMAPSv02 LLD25、OpenFace22、已有转写的CTC词定位、50个相对时间窗、V/O/P、coverage和来源映射。本文补充验收和修复任务，不把主模型重选、情感训练或Q2/Q3实现混入Q1收尾。

本次授权包括：补充必要测试/评估脚本、修复实现错误和数据读取错误、补日志、按证据重算受影响结果、重写报告。不需要每发现一个普通bug就停止请求许可。不能为通过检查删除样本、改标签、替换原始素材、虚构参考标注或随意放宽阈值。

## 2. 最终必须给出的结论

### 2.1 四种Q1结论

| `q1_decision` | `q1_complete` | 含义与下一步 |
| --- | --- | --- |
| `READY` | true | 所有必做检查通过，必要复核完成；结果、论文材料、读取与复现说明齐全，可建议Q1收尾 |
| `READY_WITH_DATA_LIMITATIONS` | true | 同上，但原始数据有已经确认且妥善处理的固有异常/天然缺失；可在明确列出限制的前提下收尾，不能宣称100条全部完整对齐 |
| `NOT_READY_FIX` | false | 存在可修复代码/配置/计算错误、质量不足或材料缺失；agent应继续修改，不停在“建议修复” |
| `NOT_READY_REVIEW` | false | 仍有影响结论的素材错配、身份或参考时间无法核验，或必要外部条件缺失；先完成可独立修复工作，再列出具体待核验事项 |

如果同时有实现错误和待复核事项，主结论用 `NOT_READY_FIX`，同时列出两类问题。对无法获得的视听判断、规则澄清等外部条件，不伪造成功；其余可做工作仍要完成。

另设独立字段 `submission_status`：`q1_materials_ready`、`pending_weight_policy`、`materials_incomplete`。Q1技术工作完成不等于全题已经可以正式提交；Q2/Q3尚未完成、总附件50MB和预训练权重提交口径仍需单独说明。不能用这个外部口径拖住已经合格的Q1技术结论，也不能据此豁免Q1自身结果缺失。

### 2.3 不能通过降低覆盖率来“修好”质量

每轮同时报告全100条、可接受配对样本、参考抽查样本三个范围。被拒绝的词、被隔离的样本和视觉漏检必须保留在相应分母或失败清单中。不能把难样本全部置零，再用剩下几条的低误差证明整个方法合格。

原始错配与实现缺陷的区别必须有证据：原MP4本身配音/错音轨，是数据限制；程序取错流、取错文件、忘记加偏移，是实现错误。OpenFace在清楚可见的人脸上持续失败或CTC在清楚匹配的语言上大量定位失败，是算法/实现质量问题，不能统称为“源数据不良”。

## 3. 准备与最小评估程序

### 3.1 执行前检查

先读项目README、实现说明和已有运行记录，确认实际CLI及run路径。检查以下材料可用：

```text
manifest / sample_index / 原始Excel与100个MP4
config / environment / 实际模型来源与代码版本
compact50 / native / words / 子词映射 / 音视频源帧表
三模态CSR来源映射 / bin_quality / status / diagnostic
原始OpenFace CSV / 派生WAV / 已选源帧图像
已有alignment_review及target_face_segments表
```

缺少原生/映射等本来应生成的材料，先补实现或重跑相关阶段，不将检查标为“不适用”。原素材损坏与派生文件被漏写分别处理。不要先删除原run、覆盖第一次结果或改动原始数据来清理现场。

### 3.2 评估脚本的职责

新增普通脚本 `scripts/evaluate_q1.py` 与必要的 `tests/test_q1_acceptance.py` 即可。可拆小辅助模块，不增加数据库、服务、内容哈希系统或额外调度框架。已有正确的测试可以复用；缺少实质性断言才补，不重复编写同一套测试。

脚本至少支持：

```text
--run-dir       必填：待评估结果
--output-dir    必填：本轮检查输出目录
--reference-dir 可选路径：视听复核、词边界与帧参考表；缺失会影响判定
--replay-dir    可选路径：独立重提取结果；缺失时复现检查为未完成
--phase         inventory / numeric / quality / reproduce / report / all
```

`all`只执行评估和生成结论，不悄悄改变提取参数/原素材。agent根据失败结果修改实现，再显式重跑。`report`必须由当前检查数据生成，不能用一篇手写总结覆盖失败状态。

检查结果用 `PASS/FAIL/UNVERIFIED/NOT_APPLICABLE`，其中：UNVERIFIED不算PASS；NOT_APPLICABLE必须注明为何没有评估对象，不能用于依赖没装好、缺文件或没有做检查。脚本遇到部分失败仍尽量生成完整检查结果与报告。

## 4. 结果表：必须收集哪些数据

### 4.1 `sample_results.csv`：100条完整结果

每条样本至少包含以下字段组。绝对路径只在服务器内部诊断使用，对外材料使用相对路径，避免暴露用户名/机器路径。

| 字段组 | 字段与含义 |
| --- | --- |
| 主键 | sample_index、sample_id、video_id、clip_id、video_relpath |
| 媒体 | duration_s、audio_start_s、audio_end_s、video_start_s、video_end_s、原音轨连续支持并集秒数、原视频展示支持并集秒数、原采样率、重采样率、原解码帧数、选帧数、显示宽高 |
| 序列 | text_words、text_subwords、audio_native_rows、vision_native_rows、最终三模态形状、valid_length、bin_width_s |
| 词定位 | spoken_words、candidate_aligned_words、accepted_aligned_words、unaligned_words、diagnostic_wer |
| 可用性 | T/A/V各自observed窗数、平均coverage、有效时长、paired_use、joint_observed_bins |
| 质量 | processing_status、pairing_status、各分支状态、错误原因、内容核验状态、必要复核是否完成 |
| 来源 | 输出相对路径、典型时间线/证据路径、问题编号 |
| 资源 | 各阶段耗时、实际设备、派生结果字节数 |

原生长度、observed窗数、coverage、状态是不同信息，不能合并成一个“有效长度”。失效数据仍占一行，值未知时使用空值并解释，不写伪造的0秒原视频。

### 4.2 `modality_results.csv`：300条模态记录

每行主键为 `(sample_id, modality)`。字段至少含：提取器/模型名与版本、feature_dim、native_rows、eligible_rows、bin_count、observed_bins、支持区间并集秒数、片段覆盖率、模态内部覆盖率、异常类型、提取是否运行、是否实际产生有效观测、输入本身是否具有可提取证据。

对没有独立文字文件的T，输入引用原Excel的text和原文字符表；A引用当前MP4的所选音轨；V引用当前MP4的所选视频流。不能把“模态文件对应关系”写成不存在的独立原始WAV/JPG。

### 4.3 汇总表的分母规则

所有比例同时保存分子、分母、值和单位。分母为0时写null和 `not_applicable_reason`，不把0/0记成100%。不先四舍五入再比较阈值；报告比例保留1位小数、时间误差保留3位小数，原始CSV保留完整精度。

分别给出：

- 全100条统计：失败/隔离保留，反映真实材料可用性。
- 对应输入可评估子集统计：由原素材核验决定，而不是由模型是否输出好结果决定。
- 有参考标注子集统计：附样本ID、样本量和抽样规则，不外推为全100条真值准确率。

sample-level均值与duration-weighted值都要标明；不要用“平均覆盖率”隐藏采用了哪种权重。

## 5. 全量结构、数学与来源验证

### 5.1 必须100%满足的实现正确性检查

| 检查 | 通过要求 | 不通过时的主要定位方向 |
| --- | --- | --- |
| 主键集合 | 原表100个主键与manifest、index、结果集合完全相同；重复/缺失/额外均为0 | Excel sheet、ID整数化、文件匹配、异常跳行 |
| 数组顺序 | 每行sample_index与主键关系一致，三模态、掩码、时间表同序 | 各阶段独立遍历顺序、多进程汇总顺序 |
| 数组规格 | T=(100,50,768)、A=(100,50,25)、V=(100,50,22)，其余遵守实施说明 | 配错提取器、88维Functionals、截前缀、错误stack |
| 有限数值 | 主输出NaN/Inf计数0；原始坏值有原因且不被标成功 | 空切片均值、0除、工具输出、无记录nan_to_num |
| 时间结构 | D可用时50窗连续覆盖[0,D]，宽度D/50；失败行明确占位 | 音视频分别归零、浮点单位、容器duration误用 |
| 掩码 | V/O/P仅0或1；Q1 P全0；V与结构而非内容一致 | 以全零反推缺失、把无人脸当padding |
| 空窗 | O=0时对应特征和coverage为0，且存在原因 | 无脸/无词前向填充、失败帧压紧时间 |
| 原生来源 | source_id能连接正确样本/模态的原生行；父词、子词和源帧映射一致 | 全局/局部字符offset混用、源帧与抽帧编号混用 |
| 聚合贡献 | 相交的有效来源不漏不重；CSR端点合法；权重与交叠一致 | 子词重复、边界归属、均值除数错误 |
| coverage | 独立区间并集重算一致，不把重叠时长直接相加 | 音频窗口重叠、重复低fps帧、视觉间隔补齐 |
| 角度 | 第17–21维周期处理正确；退化圆均值依照规则标不可用 | 角度当普通实数平均、单位混淆 |
| 隔离 | suspected/confirmed_mismatch/unverifiable均paired_use=false；受影响T区间未被接受 | audit顺序、review未生效、候选时间当真值 |
| 标签边界 | 特征计算与对齐不读取label/annotation，未引入其他情感数据 | 特征选择或阈值用情感标签、样本筛选泄漏 |

所有待评估样本均不得为not_processed。存在源数据不可恢复的问题可以保留failed/partial，但必须经过第13节的数据限制判断，不能仅凭“代码写了failed”就关闭问题。

### 5.2 独立重算，不能让同一个错误验证自己

评估脚本从原生区间与最终eligible出发，另写直接、容易审阅的交叠/并集/均值计算，不调用生产 `pool50()`，也不把生产CSR里的weights当作正确答案。对**全部100×50×3个模态窗**核对：原生贡献集合、交叠时长、归一化权重、O、coverage和特征值。

容差固定如下，超过时记录sample_id、bin、modality、dimension、实际值、参考值与误差：

```text
主键/索引/source_id/掩码/贡献集合：完全一致
秒数、窗口边界、交叠时长：绝对误差 <= 1e-7 秒
权重：绝对误差 <= 1e-6；非空窗权重和与1相差 <= 1e-6
coverage：绝对误差 <= 1e-6
普通float32特征：abs(x-y) <= 1e-6 + 1e-5*abs(y)
角度：abs(atan2(sin(x-y),cos(x-y))) <= 1e-5 弧度
```

额外回到原媒体检查，而非仅核对已经同源生成的派生表：

1. 全100条用ffprobe/PyAV重新读取选定流的首尾PTS和duration，核对t0、a0、D的定义；记录时间来源与估计末帧duration。
2. 短/中/长样本各查首、中、末源帧，以及全部报警位置，验证导出PNG确实来自记录的原帧/旋转规则。
3. 相同样本的原MP4与派生WAV对比内容及音轨范围，查漏头尾、不同音轨和重采样后偏移。
4. 从至少3个真实样本各选1个跨窗词/声学区间/视频帧，报告可手算的贡献项。

这里的数值通过证明实现符合数学定义，不证明CTC找到了正确发音位置；内容和实际时间误差由后面独立检查。

### 5.3 必要回归用例

复用实施说明中的字符映射、长文本、子词权重、晚起音轨、音频缺段、低fps、区间并集、合法零值、中间失败帧、角度环绕、P语义、整段错配、保留失败样本测试。针对本轮新发现的bug，补一个能在修复前失败、修复后通过的具体用例。

测试对象可以是数学构造的小数组和临时派生输入；不是新增情感训练数据。测试文件不得混入正式100条索引/统计。不要为了完成次数重复跑已经通过且不受修改影响的整套模型。

### 5.4 实际提取器配置与语义检查

还需检查真实运行参数和调用代码，防止“维度相同、含义却错了”：

- BERT确实使用指定模型的last_hidden_state，处于eval模式；没有用CLS、pooler或截前768个其他特征冒充词向量。选一个多子词父词，按真实token映射独立复算均值；存在跨chunk重叠时，再核对“先合并同一token的重复上下文，再做父词均值”的顺序。
- openSMILE确实为eGeMAPSv02的LowLevelDescriptors，25列名称与顺序一致，行时间来自真实输出；不能把88维Functionals截成25维。重提取代表样本时保留原工具表，抽首/中/末有效行核对数值和区间。
- OpenFace读取指定17个AU强度列及5个弧度角度列，不能混入AU presence、位移、像素坐标；实际success/confidence、目标选择与原CSV一致。抽查帧同时检查原CSV到22维数组的取列关系。
- CTC实际载入指定ESPnet模型及其原配置/全局归一化，词表与模型匹配，帧时间计算用实际编码输出；不能只在报告中写了正确模型名。词时间比较使用被接受状态，candidate与diagnostic不混入正式参考指标。

这些核对可结合第11节重提取进行，不要求为同一事实重复启动模型；保存检查到的参数、列名、父词/行/帧ID和数值比较结果。仅跑mock或只看数组shape不能替代这项检查。

## 6. 全量必须报告的基础指标

### 6.1 完整性和处理状态

| 指标键 | 定义 | 解释/目标 |
| --- | --- | --- |
| `sample_accounting_rate` | 有唯一结果或明确失败记录的原样本数 / 100 | 必须100%；不是提取成功率 |
| `source_link_rate` | 主键→原视频/原文→输出的关系正确条数 / 100 | 本批应为100%；不足先查读取/传输；确证原材料缺失时如实报告不足并按第13节处理，不能谎称已链接 |
| `n_ok,n_partial,n_failed,n_not_processed` | 四种processing_status数量 | 合计100；n_not_processed必须0 |
| `branch_execution_rate_m` | 已实际调用对应提取器的样本数 / 100 | 运行过不等于成功；另列运行成功与失败数量 |
| `branch_resolved_rate_m` | 已完成该分支，或已确认原输入不存在/不可用并妥善处理的样本数 / 100 | 区分执行完、自然缺失和环境失败；依赖未装不算已处理 |
| `sample_observation_rate_m` | 至少1个有效窗的样本数 / 100 | T/A/V分别报告，不要求天然全模态完整 |
| `paired_sample_rate` | paired_use=true样本数 / 100 | 不等于配对正确率 |
| `three_modal_sample_rate` | paired_use=true且T/A/V各至少1个有效窗的样本数 / 100 | 仍不表示三个模态在同一个窗均有观测 |
| `unresolved_issue_count` | 未定位/未复核/未修复的问题条目数 | 必做问题未解决时不能无条件收尾 |

### 6.2 片段覆盖、模态内部覆盖与共同覆盖

对样本i，窗宽为Δ_i=D_i/50，O和C分别为observed和coverage：

```text
observed_bin_rate(i,m) = Σ_k O(i,k,m) / 50
accepted_support_s(i,m) = Σ_k C(i,k,m) * Δ_i
clip_coverage(i,m) = accepted_support_s(i,m) / D_i

macro_clip_coverage(m) = mean_i clip_coverage(i,m)，仅D有效的样本
duration_weighted_coverage(m) = Σ_i accepted_support_s(i,m) / Σ_i D_i

joint_observed_bins(i) = Σ_k [O_T=1 且 O_A=1 且 O_V=1]
```

D无法建立的样本不进入秒数分母，但必须报告排除数量；全100条的sample_observation_rate仍将它们计作无观测。不能删除困难样本后只报告高覆盖率。

`joint_observed_bins`只是同窗均有数据，不保证三个模态支持区间在窗内真正相交。另用最终接受支持集合 `S_T,S_A,S_V` 计算：每个集合为eligible原生区间与该模态最终O=1窗口的交集，再求并集。必须去掉圆均值退化等造成的整窗拒绝区域；不能直接用全部原生eligible区间代替最终支持。

```text
joint_support_s = length(S_T ∩ S_A ∩ S_V)
joint_time_coverage = joint_support_s / D
```

仅在paired_use=true时解释为“可配对三模态共同支持”；否则单列数学交叠、标注内容配对无效。不能用 `min(C_T,C_A,C_V)` 代替真正区间交集。

模态内部指标另外计算：

- 音频：有效声学支持秒数 / 可确认的原音轨连续支持秒数；另报提取未覆盖的开头/末尾秒数。静音仍在分母内。
- 视觉采样覆盖：已选源帧展示区间并集 / 原视频展示支持；反映25Hz采样的保守支持。
- 视觉质量覆盖：原生层已接受目标脸支持并集 / 已选源帧支持并集；反映人脸/身份处理，不能把高fps降采样造成的间隔全部算人脸失败。与最终视觉clip_coverage分开，另列圆均值退化后损失的支持秒数。
- 文本：接受定位的可发音父词数 / 可发音父词数；与词时间支持/D分别报告。停顿窗没有词不意味着文字漏掉。

每个覆盖指标报告宏平均、P10/P50/P90、最小值及最低5条具体ID；另给全100条逐样本数值。全零视觉、无词、坏音轨、配对隔离各自统计，不合并成“缺失”。

### 6.3 特征数值与退化检查

只对eligible原生行和O=1输出统计，分别保存n、min、P01/P50/P99/max、均值、标准差、零值比例。角度除范围检查外用圆统计，不把±π环绕误判为大幅异常。BERT补充词向量范数分布；AU补充超出0–5的行数和来源；声学列名必须与指定工具一致。

重点调查但不直接定罪的情况：跨多个不同样本的BERT词向量完全相同、声学所有列恒定、全部视觉是同一行复制、每个样本都相同50步前缀。单个AU常为0、无声F0为0可以正常；没有人工AU真值时不报告“AU识别准确率”。

每个异常必须回到输入和原生输出判断。范围外或低方差是诊断信号，不能为美化统计直接剪裁/加噪声/标准化。此处的统计量仅用于描述结果，不作为Q2训练的全数据归一化参数。

执行者可为具备可靠视听工具的agent或实际复核者。记录真实工具/方式，不能把纯文本推断记为“听过音频”。若无法视听核验，自动排查和可独立完成的代码修复仍继续，但未核验条目明确列为 `not_reviewed`，本阶段为NOT_READY_REVIEW。

### 7.4 已确认数据问题的关闭要求

源数据问题可以关闭“继续修复”项，但必须同时具备：原始来源证据、具体受影响模态/时段、原样本保留、适当隔离/掩码、处理后验证、报告中的影响数量。reviewed_match不能靠改一个CSV状态获得，必须有可复核依据。

固定偏移若来自实现的时间换算，修代码并重提取；若来自素材内部真实异步，先按源问题记录，不以反复移动音轨直到指标变好作为修复。整个音轨属于别的内容时不能从其他附件借音轨补回。无法证明边界的局部异常按保守范围隔离，并披露损失。

## 8. 词级时间质量：建立小型独立参考，报告误差与拒绝率

### 8.1 参考集的选择

参考集用于本题时间质量审计，不是新的情感训练数据，也不是独立外部测试集。

1. 先依据第7节原素材核验，得到原文—音频确实可对应、具有可辨识言语的样本集合G。**不能依据CTC是否成功或paired_use输出筛选G**；原素材正确但CTC失败的样本必须仍可被抽到。
2. 按 `(duration,sample_id)` 排序，将G等分为10个连续时长层；每层选择中位位置的一条，尽量覆盖不同video_id。来源重复时取该层最近的未使用来源；没有其他来源则保留并记录。G不足10条时取全部。
3. 每条先按父词顺序等距选6个词，包含首/末可发音词；不足6个取全部。待选词ID在查看CTC预测前确定，保存清单。
4. 目标为至少10条、60个可评分词。因词本身难以分清边界而不足时，按固定词序/剩余样本的时长顺序补充，不能专挑高CTC分数词。若真实可评估输入不足，只能使用全部可获得参考并注明缩小范围，不能伪造凑数。
5. 全部已知对齐异常片段另作挑战案例，和分层参考指标分列，避免混淆抽样分布。

确定性实现：G不少于10条时按排序索引用 `np.array_split(indices, 10)` 分层，每层中位索引取 `(len(layer)-1)//2`；需替换重复video_id时按离该中位的索引距离、再按原索引升序选择未使用来源。词等距位置取 `floor(j*(W-1)/(n-1))`，其中 `n=min(6,W)`、j=0…n−1；n=1取唯一词，W=0不造参考。补充词先按已选样本顺序及word_id升序取未选可评分词，再按剩余样本排序补充；每次排除必须保存原因。抽样不使用情感标签或模型分数。

G或可用参考词确实不足目标时，必须由全量内容核验提供原因；如果只是没有时间标注、工具能力不足或模型拒绝太多，属于尚未完成，不是数据量不足的豁免。

### 8.2 标注规则与文件

先根据原音频听取、局部回放及波形辅助标出词的发音开始与结束，再显示CTC候选进行比较，避免参考边界照抄模型。开始取该词首个可听发音的起点，结束取末个可听发音的终点，词间停顿不并入词本体。统一使用公共秒轴，正确加a0。

父词含数字展开/缩略词多音节时，参考区间覆盖该父词实际对应的完整发音；纯标点不设发音边界。共同发音导致边界难以区分时标uncertain并说明，不以静音阈值硬造边界。

`word_reference.csv`至少保存：sample_id、word_id、raw_word、char_start/end、ref_start/end、boundary_uncertainty_s、reference_status、reviewer_id、evidence。reference_status为 `scorable/uncertain/not_spoken/text_mismatch`。边界不确定性>0.05秒的词不参与精细误差统计，但仍报告数量及原因；需按上节补充其他预定候选。

对至少20%的参考词再听一遍，选在各时长层均有覆盖；第二次先隐藏第一次数值。边界差>0.10秒时复核并记录最终决定。只有一个执行者时，称“同一执行者复核”，不能称多标注者一致性。

agent没有可靠听取/时间标注能力时，只生成待标注词表并报告NOT_READY_REVIEW，不能让另一套ASR输出冒充人工真值。可先完成其他验证和修复。

### 8.3 误差公式与必须输出的数值

设参考区间为 `[s*,e*)`，被接受的预测为 `[s,e)`：

```text
start_error_s = abs(s-s*)
end_error_s   = abs(e-e*)
boundary_error_s = (start_error_s + end_error_s)/2

signed_start_bias = s-s*
signed_end_bias   = e-e*
word_interval_iou = overlap([s,e),[s*,e*)) / union_length([s,e),[s*,e*))
error_in_bin_widths = boundary_error_s / (D/50)

reference_acceptance_rate = 有已接受时间的scorable词数 / 全部scorable参考词数
within_200ms_rate_all_refs = 已接受且首尾误差均<=0.2秒的词数 / 全部scorable参考词数
```

没有被接受的预测时，误差列为null、status为miss；它仍留在reference_acceptance_rate和within_200ms_rate_all_refs的分母。不能给miss填0误差或从所有分母中删掉。

报告：参考clip数/video_id数/词数、不确定词数、接受/拒绝数；首/尾误差与boundary_error的P50/P90/max；有符号均值偏差；IoU的P10/P50/P90；按窗宽归一化误差P50/P90；全参考词的200ms比例；误差最大的10个词ID。另报告candidate时间的误差，但不要与已接受结果混算。

同时给词级整体统计与按样本先算再平均的统计，避免长片段词多而独占指标。分位数使用NumPy `quantile(method="linear")`，小样本明确n，不编造置信区间或全数据泛化结论。

### 8.4 本次工程质量目标与未达到时的动作

在确实匹配的参考输入上，本次预设目标为：

| 检查 | 目标 | 未达到的处理 |
| --- | --- | --- |
| 参考词接受率 | ≥90% | 逐条分析拒绝；查词表、数字规范化、UNK、得分/身份隔离误传，不以放宽阈值为第一反应 |
| boundary_error P50 | ≤0.15秒 | 查整体时间偏移、CTC帧时长、发音区间定义 |
| boundary_error P90 | ≤0.35秒 | 查局部错配、长停顿、尾部截断、异常词及模型定位质量 |
| 平均首/尾有符号偏差 | 两者绝对值均≤0.10秒 | 查公共起点、重采样/编码帧换算与系统性边界偏差 |

这些是本项目用于发现不可忽略问题的预设质量目标，不是题目官方阈值，也不是行业保证。正式数值以实际测量为准；未达到时默认NOT_READY_FIX，完成原因定位和改进后复测。不能因观察到结果不好就直接把目标改大。

若 `error_in_bin_widths` 的P90>1，还必须回看至少5个最差词（不足5个则全查），检查错误是否把词分配到明显错误的50窗。绝对误差达标不自动说明短片的细时间窗足够可靠。确认发生明显错误对应则仍不能收尾；若误差主要为参考定义不确定，应如实降低精度声明，保留依据，不说“秒级精准定位已证实”。

即便目标达到，也只能陈述“在按规则选取的n条/m词参考检查中达到这些数值”。完成报告不得将其写为全100条逐词真值准确率。

## 9. 视觉有效性、身份与声学支持的专项核对

### 9.1 视觉抽样与参考标注

使用第8节同样的10层抽样算法，但从**全部具有可解码原视频的样本**独立抽取，不以文字—音频匹配作为视觉抽样条件。每条从**已选源帧**等距选10个位置（第8节公式将n改为min(10,帧数)），含首尾，不足10帧取全部；另加所有身份变化/多脸报警区间的代表帧。基础抽样与挑战帧分列。选择时不看OpenFace置信度，不只挑成功帧。应有视频而程序没有导出帧的，先修导出错误，不悄悄换样本。

对每帧记录：sample_id、source_frame_index、image_index、public_time、原图像路径、是否有可识别目标脸、是否仅部分可见/严重模糊、是否可确认人物、当前输出是否被接受、选中face_id/episode是否正确、参考结论与证据。输出的face_id仅为跟踪槽位，不作为参考身份真值。

“可评估目标脸”指原素材可确认目标、面部清楚可辨且没有使关键部位无法判断的严重遮挡；不能因为OpenFace没检测出就标不可评估。侧脸/模糊/遮挡单列。仅能确认脸存在而不能确认说话人物的，身份状态为uncertain。

### 9.2 视觉指标与错误判定

```text
accepted_frame_validity = 经参考确认接受合理的帧数 / 被程序接受且已审阅的帧数
clear_target_recall = 被程序正确接受的清楚可评估目标帧数 / 全部清楚可评估目标参考帧数
wrong_target_count = 接受了错误人物的帧数
no_face_false_accept_count = 原画面无目标脸但仍作为目标脸接受的帧数
```

全部分子/分母和具体帧ID必须留存。错误人物、无脸冒充成功、复用错帧、拿跟踪槽位当永久身份，**在已审阅集合中修复后必须为0**。clear_target_recall低于80%时必须定位原因，不能仅把视觉全设为缺失；这个值是工程调查标准，不是人脸基准数据集准确率。

因多人但能通过素材核验确认目标时，应补正 `target_face_segments.csv` 并重新筛选已有CSV，不必重新提取全部图像。确认目标后仍不过质量阈值的帧不能人工改success/confidence。

全部源视频确实无可评估脸时该项可不适用，但需证明是输入限制；整个OpenFace依赖失败、选帧错序或模型缺失不能豁免。不能从脸动作直接给出正负情感“真值”，也不以AU大小与情感标签单调对应作为通过条件。

### 9.3 声学支持与合法零值核对

在短/中/长样本及全部音频异常样本上，核对原音轨与派生WAV内容、起点、持续时间，确认没有错声道/错音轨、剪掉头尾或压掉缺段。至少选一段真实停顿和一段发声（若存在），比较相应声学行、有效区间及O，确认静音的合法零输出仍可观测。

报告音频派生时长残差的P50/P95/max及超0.02秒ID、内部PTS缺段/重叠数量、声学有效行率和音轨内部支持覆盖。超限先查AAC首尾处理、源PTS、采样单位和重采样链路，不能直接把视频长度当音轨长度强制拉伸。

若原始PCM可正常解码而A整体失败，属于必须修复的实现/依赖问题；若真实内部缺段导致本版无法安全建立连续波形，应保留源证据与当前隔离策略，并评估是否造成必要结果无法成立。只写“异常已mask”但没有追查原素材，不算关闭。

## 10. 50窗的信息压缩与方法合理性

### 10.1 必做的粒度描述

报告所有样本窗宽D/50的min/P50/P90/max；每窗贡献词数、每词跨窗数；音/视频原生行数与50窗行数之比；视觉选帧比例和真正支持覆盖的区别。列出最长样本和混合最多词的窗口。

在典型例中说明：BERT表示含上下文；均值压缩会丢失窗内先后顺序；低覆盖窗不等于完整观测；图像源展示区间的保守支持不代表未选帧一定无表情。不要仅以尺寸小、文件小论证方法保留了全部信息。

### 10.2 无标签的回投误差

复用已经提取的原生特征，不重新训练。对一个已接受原生记录i，令它与观察有效的输出窗交叠为u_ik，将这些窗按交叠归一化回投：

```text
beta_ik = u_ik / Σ_k u_ik
x_hat_i = Σ_k beta_ik * X_k
```

角度回投同样用圆均值，退化结果记不可评估。无回投支持的原生记录单独计数，不能从报告消失。度量分别使用：

- 文本：词向量与回投词向量的 `1-cosine_similarity`；零范数另列异常。
- 音频：每列报告RMSE，另除以该列有效原生值的P95−P05得到尺度化RMSE；尺度≤1e-8的列单列为近常量，不硬除以很小数。
- 视觉AU：17列分别报告RMSE及RMSE/5；角度报告圆周绝对误差的P50/P90，单位弧度。

尺度统计只用于当前特征压缩描述，不进入提取器或后续模型训练。文本、音频、AU、角度分别列结果，不把单位不同的值平均为一个“总体保真度”。重叠分析窗具有依赖性，这些差异不等于情感预测损失或统计独立误差。

为避免只挑好看例子，每模态列误差最大的3条样本/局部位置，回看实际原素材和原生变化。这一步是识别压缩/聚合问题，不能直接把工具自身噪声称为情感事件。

### 10.3 何时需要追加比较

主输出仍为50窗。只有以下情况追加同原生特征的100窗诊断：独立重算通过，但明显短时变化在50窗被平均到难以说明；很多词落在同一窗而典型证据无法区分；或最差误差案例的来源表提示粒度不足。

仅对受影响案例和2条正常对照计算，不开启大规模参数搜索。比较窗宽、回投误差、观测覆盖、特征体积和原素材案例，说明50窗是否足以支持当前Q1展示。100窗改善数值不自动证明更高情感性能。

若50窗导致核心对应效果无法成立且需要改变主输出粒度，报告NOT_READY_FIX与具体证据，先修可修的实现错误，再给出明确方法调整建议；不能暗改K同时沿用旧报告称已通过。普通可解释的平均损失可作为方法限制，不要求所有压缩误差为0。

## 11. 实际复现、运行资源与成果读取

### 11.1 代表样本独立重提取

从已经完成内容核验的样本按 `(duration_s, sample_id)` 排序，选最短、中位、最长各1条；再补1条已确认错配及1条视觉身份/缺失案例，若该类不存在则不补。去重后一般3–5条，保存 `replay_ids.txt`。若最短/中位/最长不能覆盖实际可用的三模态提取，另补最先出现的、能够核验三模态的样本，并写明原因。

在**新run目录**从原Excel/MP4重新执行这些样本的媒体解析、BERT、CTC、openSMILE、OpenFace、audit和pool。预训练模型和已安装环境可以复用，不能复制旧run的原生特征、WAV、OpenFace CSV或compact结果冒充重提取。经过确认的内容复核表、人物目标表可作为显式输入复用：复核事实没有变，不必再次人工从头标注；程序仍须将规则重新应用于新提取结果。

重新打开一个shell，按照项目README的相对路径命令运行，记录实际命令、返回码、源码Git版本、配置、依赖版本、模型目录版本、GPU型号和设备。无需无理由重装已经合格的环境，也不要求再下载同一权重。若实际推理仍偷偷联网寻找缺少的文件，应修正模型本地加载与下载说明。

### 11.2 重提取比较规则

只比较 `replay_ids.txt` 指定的样本。子集run中的其他manifest行可为not_processed，不据此把子集复现误判为全量失败；正式主run仍必须全100条已处理。

| 对象 | 同版本、同设备复现要求 |
| --- | --- |
| ID、原媒体帧号、文字/父词/子词映射、数组形状、列名 | 完全一致 |
| V/O/P、paired_use、最终eligible、贡献source_id集合 | 完全一致；变化必须查明，不能用浮点容差豁免 |
| 源媒体PTS、公共起点、输出窗边界 | 按第5节时间容差 |
| 模型产生的词边界 | 绝对差≤1e-4秒，并核对是否改变窗贡献关系 |
| 原生与compact普通浮点值 | `abs(new-old) <= 1e-5 + 1e-4*abs(old)`；分别列最大误差和超限元素数 |
| 角度值 | 圆周差≤1e-4弧度 |
| coverage与聚合权重 | 绝对差≤1e-6 |

先用新run自身的原生记录重新执行第5节数学验证，再比较两次提取值。不能因为允许模型浮点误差，就允许聚合公式算错。异常时依次查eval模式、随机种子、混合精度、CUDA/CPU分支、音频解码、OpenFace目录与参数、配置是否一致。记录真实差异，不临时提高容差来消除失败。

若服务器更换了设备或工具版本，称为“跨环境比较”，不能替代本轮同环境复现；保存两侧环境差异，并对掩码/来源变化逐条核验。不会影响最终输出的诊断文本或日志顺序差异可解释，不要求日志逐字相同。

### 11.3 资源数据

报告全量运行总墙钟时间、模型初始化时间、各阶段耗时、每样本耗时P50/P90/max；指出哪些阶段并行，不能把并行子任务时间直接相加冒充总墙钟时间。读取不到历史运行资源时，在实际重提取中测量并注明样本范围，不外推为已经测量过的全100条峰值。

## 12. 报告必须长什么样

### 12.1 机器结果的最小格式

`checks.csv`每行是一个可定位检查，至少包括：

```text
check_id, scope, sample_id, modality, item_id,
status, expected, actual, tolerance, evidence_relpath, issue_id, reason
```

全局检查的sample_id可为空；局部失败必须给出具体ID/窗/维度或时间。对于几万个重复数值失败，可以保存汇总计数和独立明细文件，但不能只留一句“数值不一致”。

`metrics.json`的每个指标保存 `value, numerator, denominator, unit, subset, n_samples, definition, evidence_relpath`。非比例指标的numerator/denominator为null，另存n_observations；真正未测得的value为null并有reason。不用字符串“100%”替代原始数值，百分比的机器值统一保存0–1。

```json
{
  "sample_accounting_rate": {
    "value": null,
    "numerator": null,
    "denominator": 100,
    "unit": "ratio",
    "subset": "all_original_samples",
    "n_samples": 100,
    "definition": "有唯一结果或明确失败记录的原样本数/100",
    "evidence_relpath": "sample_results.csv",
    "reason": "待实际检查；本例不是实测结果"
  }
}
```

报告脚本从机器结果生成表格和判定，人工可以补充解释但不能把FAIL改写成PASS。JSON禁止NaN/Infinity；CSV空值与0分开，文本按UTF-8保存。

- 时间误差、视觉抽查、覆盖、压缩与复现的实测表和必要限制，特别说明评估子集及参考来源。
- 结果读取例子、实际工具版本、核心参数和完整执行命令。

典型时间线用下面的**结构**填真实值，不能把示意符号当作实测数据：

```text
[样本ID；D；原始MP4相对路径；原文所在行]
                        │
                        ▼
[公共时间：0 ─────── t_k ─────── t_(k+1) ─────── D]
                        │          输出窗k
        ┌───────────────┼───────────────────┐
        ▼               ▼                   ▼
[父词ID/原文]     [声学行ID/25列]      [源帧ID/22列]
[参考/预测时间]   [每行真实支持区间]   [PTS及原帧展示区间]
        │               │                   │
        ▼               ▼                   ▼
[交叠秒数→权重]   [交叠秒数→权重]     [交叠秒数→权重]
        │               │                   │
        ▼               ▼                   ▼
[T_k, O_T, C_T]   [A_k, O_A, C_A]      [V_k, O_V, C_V]
        └───────────────┼───────────────────┘
                        ▼
[V结构掩码、P=0、paired_use、三者共同支持区间]
```

这里 `V_k` 表示视觉向量，`V结构掩码`表示时间结构掩码，报告中必须写明避免同名误读。50窗对应不代表三模态在窗内每一瞬间都同时存在。

### 12.4 Q1与Q2/Q3的实际闭环边界

对后续任务交付：公共时间定义、掩码含义、质量/错配规则、特征列名、来源接口、100条样本索引与已确认问题。下游据此知道哪些配对可用、哪些证据不能使用。

报告必须明确三点：

1. Q1的768/25/22维与附件2/3/4给定的文本/声学/视觉序列不是同一套数值。不能只因文本768维或长度50相同就直接互换。
2. 附件2的50位置不自动等于Q1的相对时间窗；附件3/4某行对应哪一秒，没有原始映射时仍然未知，Q1重提取不会补证官方矩阵的逐行时间。
3. Q1全部100条与附件2已有重叠，Q1验收未使用情感标签优化特征，不把整批100条加入Q2训练集；后续严格遵守官方划分。Q3可以引用质量规则，但不把Q1的时间定位误差当作Q3恢复误差。

## 13. 能否作为Q1完成：明确判定规则

### 13.1 收尾必须满足的事实

下面各项应能从当前报告与机器表查到，不另建复杂审批系统：

| 编号 | 收尾要求 | 不能以什么替代 |
| --- | --- | --- |
| C1 | 100个原主键全部保留、有结果或已确认原因；not_processed=0；不篡改素材/标签 | 只有100行空壳、删除困难样本 |
| C2 | 第5节结构、来源、数学、掩码检查通过；没有未修计算错误 | 文件存在、日志写success |
| C3 | 全100条内容核验有实际证据；影响接受/配对的疑问已解决或已证实为天然不可建立配对的输入 | CTC高分、只看首帧、全部标unverifiable却称已审完 |
| C4 | 独立参考抽样按第8节完成并达到时间质量目标；样本不足仅限经全量核验证明没有足够可评估输入 | 只挑低误差词、拒绝词从分母消失、缺工具当数据不足 |
| C5 | 已审阅视觉错误身份/无脸误接受为0；明显漏检和声学失败均已定位，清楚有效输入上无未解决系统性提取问题 | 视觉/声学全部置零，降低confidence标准冒充修复 |
| C6 | 三模态特征与覆盖有真实解释，典型案例至少1条在真实共同支持区间可核验；50窗的对应效果可成立 | 三个模态各找不同样本拼成“典型例” |
| C7 | 第11节独立目录重提取完成并满足比较要求；读取例子可直接运行 | 复制旧特征、只运行mock测试 |
| C8 | 当前结果的全量指标、100条表、参考表、问题证据、报告、读取/复现说明齐全且相互一致 | 只有方案、没有实测数值或没有实际文件 |
| C9 | 所有可修代码/部署/配置错误已修复；所有残留数据限制有来源证据、处理和影响说明 | 清空错误列表、把部署缺文件标成源损坏 |

原素材完整而服务器少传了MP4、模型没下载好、路径错、解码器未装，均不能算固有数据限制。本次已有统计显示原始100条可对应，若服务器映射不同，优先查传输/解压/读取；确实发现源材料与既有统计有出入时，要保留事实证据和说明。

不设“所有模态覆盖必须100%”这一不合理条件，因为真实说话停顿、无脸和数据错配本来会造成缺失；也不设一个低覆盖率就能包过的统一阈值。替代要求是：**全部异常/低覆盖案例都能追溯，输入本来可用却未提取的情况已解决，必要参考指标达标，且存在能说明方法成立的真实三模态典型证据。**

clear_target_recall<80%的样本必须逐帧解释低于调查值的原因；清楚目标持续漏检仍属于未解决质量问题，不能仅写“OpenFace能力有限”就收尾。少量边界姿态等模型局限经复核可列方法限制，但需报告可评估分母、漏检ID与对必要典型证据的影响，不能改写参考可见性来提高召回率。

若可评估输入确实不足10条/60词，用全量内容核验说明不足原因，参考检查覆盖所有可用样本并按规则尽量取词；仍须有实际可测参考与真实三模态典型例。**没有任何时间参考或没有任何可靠三模态例时不能收尾**，不能把所有质量检查都写为不适用。

### 13.2 什么时候允许带数据限制收尾

只有同时满足下列条件，才可 `READY_WITH_DATA_LIMITATIONS`：

```text
[异常由原始材料本身造成，有具体来源和视听/时间证据]
                             │ 是
                             ▼
[原样本与标签保留；受影响模态/时间和隔离规则明确]
                             │ 是
                             ▼
[不存在可修未修实现错误；独立数值/来源检查通过]
                             │ 是
                             ▼
[全部C1–C9成立；质量证据不是靠全删/全mask制造]
                             │ 是
                             ▼
[报告列明异常ID、数量、覆盖损失及下游影响]
                             │ 是
                             ▼
[READY_WITH_DATA_LIMITATIONS，建议Q1技术收尾]
```

例如：已确认原音频与转写整段无关，保留原样本和独立音/视觉特征，T时序依规则缺失，paired_use=false，其余可评估集合的计算/质量/复现均合格。可带此限制收尾，但不得说这条已完成三模态语义同步。

相反：听不清或当前agent无视听能力，只能标uncertain；这属于证据不足，并非已证实固有错配。所有可独立修复工作完成后仍缺这个必要判断，结论为NOT_READY_REVIEW。原始配音/画外音已被可靠确认、客观不存在可指定的画面说话人，可以作为已明确的数据事实处理，不要求凭空建立身份。

### 13.3 判定顺序与输出文件

```text
是否有未修实现/配置错误、未达质量目标或应补但未补材料？
  ├─ 是 → NOT_READY_FIX → agent继续修改与复测
  └─ 否
       │
       ▼
是否缺少影响C1–C9的必要事实、参考标注或可执行外部条件？
  ├─ 是 → NOT_READY_REVIEW → 完成独立工作并列具体待核验项
  └─ 否
       │
       ▼
是否满足全部C1–C9且没有以不适用/隔离掩盖失败？
  ├─ 否 → NOT_READY_FIX（方法不成立则明确需调整之处）
  └─ 是
       │
       ▼
是否存在已确认且正确处理的原数据限制？
  ├─ 是 → READY_WITH_DATA_LIMITATIONS
  └─ 否 → READY
```

代码可修但当前尚未修，不应改写成等待用户；必要外部条件确实缺失，则明确说明具体缺什么、影响哪个ID/结论，以及已完成的独立工作。方法核心需要改变时，先给出证据、可行调整和影响，保留NOT_READY_FIX；不能自动宣称现方法已完成。

最终 `decision.json` 必须包含以下字段；此处是字段示例，值需根据实际检查生成：

```json
{
  "q1_decision": "NOT_READY_REVIEW",
  "q1_complete": false,
  "main_run_relpath": "runs/待替换为实际run",
  "assessment_relpath": "assessment/round_01",
  "criteria": [],
  "blocking_issues": [
    {
      "issue_id": "示例：待实际检查后替换",
      "kind": "missing_evidence",
      "sample_ids": [],
      "reason": "本JSON仅说明字段，不是实测判定",
      "evidence_relpath": null,
      "next_action": "执行本方案并填写真实证据"
    }
  ],
  "confirmed_data_limitations": [],
  "submission_status": "materials_incomplete",
  "q1_package_bytes": null,
  "summary": "待执行，不代表Q1已经测试"
}
```

实际 `criteria` 逐项写C1–C9的status、reason、evidence_relpath；blocking_issues区分implementation/quality/missing_evidence/external_condition。q1_complete必须由本轮判定计算，不能由“程序退出0”直接推导。

评估脚本完成时，最终all/report可返回：0=READY或READY_WITH_DATA_LIMITATIONS；2=NOT_READY_FIX；3=NOT_READY_REVIEW；1=评估脚本自身未处理异常。分阶段执行能完成其本阶段检查即可返回0，但打印“阶段完成不等于Q1通过”。这些是**新评估脚本**的退出码，与提取CLI的退出码分别记录，不混淆。

### 14.1 每个问题的闭环记录

`repair_log.md`每个问题只需记录：问题编号、失败实测、受影响ID/阶段、最小复现、原因、修改文件/参数、重算范围、复测命令与结果、旧问题是否关闭。源码变更用普通Git版本记录，不再建立文件哈希或重复版本系统。

```text
[读取失败清单：具体ID/时段/维度/阈值]
                    │
                    ▼
[回到原数据和最早出错阶段，重现问题]
                    │
                    ▼
[判断：读取/时间/算法/审核事实/报告，定位根因]
                    │
                    ▼
[修改最小必要代码或显式复核表；补能复现该bug的测试]
                    │
                    ▼
```

### 14.2 常见失败与确定的重算范围

| 失败情形 | 优先检查和修复 | 至少重跑/复查 |
| --- | --- | --- |
| 100条缺行、重复、顺序错 | 主表sheet、clip_id字符串格式、ID连接、多进程顺序；以manifest为唯一顺序 | prepare/index；受错误映射影响的全部阶段；collect及全量验证 |
| 整段文字/音频不符 | 先对比源MP4、Excel与派生WAV；取错文件/流则修读取，源本来不符则补真实复核与隔离 | 读取错需media及后续；仅复核状态变化需audit、pool、collect、validate、report |
| 所有词整体偏早/晚 | a0、t0、采样单位、CTC帧时长与词时间坐标 | 受影响align及下游；若公共媒体起点错，所有模态时间映射及下游 |
| 明明清楚匹配却大量UNK/拒绝 | 大写BPE词表、数字展开父词关系、归一化、ESPnet模型配置/global_mvn、本地模型文件 | 修改对应text/align部分，检查原文不变；受影响词定位与聚合 |
| 原音轨正常但WAV异常 | stream选择、AAC边界、声道、解码PTS、重采样累计长度 | media→align/audio→audit/pool及下游；视频不受影响可复用 |
| 源音轨确有缺段 | 保存原PTS/内容证据，确认当前保守隔离规则适用；不能偷偷压紧时间 | 对应音频/CTC状态和下游；评估剩余证据能否满足收尾条件 |
| 人物错误、场景切换后继续同face_id | 跟踪槽位/episode、目标表、原帧身份；不能用face_id当永久人物 | 原CSV正确则vision重新筛选并复用CSV→audit/pool及下游 |
| 所有视觉失败 | 模型文件、静态AU模式、实际OpenFace命令、路径/工作目录、CSV字段、帧编号 | 依赖/命令错则真实重提取；仅筛选错则复用原CSV重新筛选 |
| coverage>1、同一帧被算多次 | 区间并集、低fps重复、source_id集合、真实展示区间 | pool及下游；若source表错误，先修media/vision对应表 |
| ±π附近均值跳到0 | 角度索引17–21、单位、sin/cos均值、退化规则 | pool及下游，补环绕与退化用例 |
| 向量全零但O=1 / 合法静音被O=0 | 是否错误nan_to_num或按全零判缺失；检查真实工具状态 | 修相应提取/筛选/pool阶段；不要统一强行修改O |
| 词时间达标但短片窗对应明显错误 | 归一化误差、边界取整、公共时间、50窗交叠 | 先修真实时间bug；仍有粒度问题按第10节诊断并明确方法影响 |
| 无法复现 | 实际版本、eval、精度、设备、配置、源文件/目标表是否一致 | 只重跑有差异的阶段及依赖阶段；修公共问题后全部代表样本复测 |
| 报告与NPZ统计不一致 | 数据路径是否旧run、零值是否当缺失、分母范围、旧表复用 | 重新collect/评估/报告；原始特征正确则不必重提取 |

公共时间轴、权重计算、掩码、字典映射、模型调用等全局逻辑修改，不能只验证最先报错的1条；必须重算全部受影响ID，并再执行全100条结构/数值检查。只修正文错字或报告格式，不重新运行模型。

### 14.3 修复前后必须一起比较质量与覆盖

每次真实修复后，使用同一原100条集合和同一参考集合记录：问题数、accepted词数/拒绝数、boundary_error、参考接受率、各模态覆盖、paired样本数、视觉误接受/漏检。内容事实更新确需变更参考集合时，保留旧集合上的比较，并单独说明新增/移除原因。

例如时间P90降低但参考接受率从95%跌到40%，不得称为修复成功；错误人物数变0却把所有清楚脸都拒绝，也未解决问题。正确隔离真实错配可能使全量覆盖下降，应写“错误接受已修正、真实可用覆盖下降”，不能写所有指标都提高。

### 14.4 什么时候可以停止修复循环

- 满足第13节并完成报告：停止，给出可收尾结论与材料路径。
- 同一根因尚未解决：继续有依据地诊断；不能连续盲目重跑相同命令，也不能第一轮发现bug就只输出建议。
- 必须依赖当前环境没有的视听复核、无法取得的指定权重或外部规则：完成所有独立工作后，记录已尝试动作、完整错误、缺少的具体条件和受影响项，给出NOT_READY_REVIEW。未修代码错误仍存在时按优先规则给NOT_READY_FIX。
- 固定方法在清楚输入上持续无法达到必要质量、需要改变核心模型/粒度：整理失败证据、已经排除的实现原因和具体调整建议，保持NOT_READY_FIX。不要自行换模型后沿用原方法名称，也不要宣布“已尽力所以完成”。

只要修改还影响当前结论，必须更新报告与decision，不能交付“新代码+旧结果+旧通过声明”。

## 15. 给服务器agent的执行顺序

### 15.1 参数与评估脚本行为

以下命令中的 `scripts/evaluate_q1.py` 是**本方案要求agent补充实现的脚本**；提取命令由配套实施说明中的项目提供，执行前检查真实CLI。评估器不需要新模型，使用实施环境已有NumPy/Pandas/PyAV等依赖；测试复用项目已有测试工具，若已有pytest则使用pytest，不另引入测试框架。

将 `Q1_ROOT` 替换为真实项目绝对路径，`Q1_RUN`替换为已生成的全量run；不要原样保留占位符执行。下面示例的run名称没有绑定日期：

```bash
export Q1_ROOT=/实际路径/q1-project
export Q1_PY="$Q1_ROOT/env/python/bin/python"
export Q1_RUN="$Q1_ROOT/runs/实际全量run"
export Q1_ASSESS="$Q1_ROOT/assessment/round_01"
export Q1_REF="$Q1_ROOT/assessment/references"
cd "$Q1_ROOT"
mkdir -p "$Q1_ASSESS" "$Q1_REF"
```

phase职责固定如下，避免实际执行时不知道下一步：

| phase | 执行内容和输出 |
| --- | --- |
| inventory | 原100条主键/产物清单、版本与处理状态；创建sample/modality结果表初稿 |
| numeric | 第5节全量独立结构/来源/数值检查及基础指标；已有必要测试由agent单独运行 |
| quality | 第6–10节质量指标；没有参考时生成待核验对象清单/空参考模板，有参考时验证并计算；从不自动填“人工确认” |
| reproduce | 验证replay目录确实按第11节重新提取，比较指定ID的结果；无replay则UNVERIFIED |
| report | 合并当前轮检查，生成report/paper/decision；未执行的必做项保持UNVERIFIED |
| all | 顺序执行以上检查并生成最终文件；缺少证据也写完整报告和不通过原因 |

各phase只替换自己负责的检查行，保留当前轮其他phase的结果。代码/结果修改后应新建下一轮评估目录，不能把旧numeric通过记录拼到新run的quality结果上。正常同轮分阶段工作可逐步补充；README说明如何由最终all重算得到一致结果。

quality生成的辅助文件至少有 `review_targets.csv`、`word_reference_targets.csv`、`vision_reference_targets.csv`、`replay_ids.txt`；目标清单包含抽样规则、基础/挑战分组、原素材定位、参考状态。源素材核验完成后才确定匹配输入集合与词抽样，不能先按高CTC分挑参考。复核事实写入Q1_REF下同名参考CSV，程序检查ID、时间坐标、必填证据与completed状态，不接受仅把空模板改名后的文件。

### 15.2 按实际依赖顺序执行

1. 确认全量run、实现说明和README一致，运行已有相关数学/回归测试。修复测试失败，再做全量检查。

```bash
"$Q1_PY" scripts/evaluate_q1.py --run-dir "$Q1_RUN" \
  --output-dir "$Q1_ASSESS" --phase inventory
"$Q1_PY" scripts/evaluate_q1.py --run-dir "$Q1_RUN" \
  --output-dir "$Q1_ASSESS" --phase numeric
"$Q1_PY" scripts/evaluate_q1.py --run-dir "$Q1_RUN" \
  --output-dir "$Q1_ASSESS" --reference-dir "$Q1_REF" --phase quality
```

2. 根据清单完成全100条内容核验，定位具体错配；按第8/9节完成参考时间/帧检查。必要时修正显式复核表并重新audit/pool等阶段。此时重新运行quality，才能获得真实质量指标；模板存在不表示标注完成。

3. 对实际发现的问题按第14节修改，使用项目CLI的显式重算功能。`--resume`不能掩盖修改过的代码/配置；重跑范围应覆盖受影响下游。保存源码版本和repair_log，完成后将Q1_RUN指向实际最终结果；如果创建新评估轮，也更新Q1_ASSESS。

4. 执行独立重提取。先按第11节选出replay_ids并完成新的prepare，再重跑指定ID。例如：

```bash
export Q1_REPLAY="$Q1_ROOT/runs/实际独立复现run"
export Q1_CONFIG="$Q1_ROOT/configs/实际已验证配置.yaml"
"$Q1_PY" -m q1_features prepare --config "$Q1_CONFIG" --run-dir "$Q1_REPLAY"
"$Q1_PY" -m q1_features run --config "$Q1_CONFIG" --run-dir "$Q1_REPLAY" \
  --ids-file "$Q1_ASSESS/replay_ids.txt"
```

prepare/run的实际分工以已实现CLI为准，不能重复初始化覆盖已有目录。将已确认复核表/人物表通过实施项目的输入路径应用到replay；若当前CLI只支持run目录中的审核文件，prepare后按README把这些表放入新目录，再执行对应audit/pool阶段。**只复用人工事实表，不复用旧计算输出。**

5. 生成最终全量评估与报告：

```bash
"$Q1_PY" scripts/evaluate_q1.py --run-dir "$Q1_RUN" \
  --output-dir "$Q1_ASSESS" --reference-dir "$Q1_REF" \
  --replay-dir "$Q1_REPLAY" --phase all
```

若本次退出2，继续定位、修改、重算和评估；退出3则完成可独立工作并输出精确缺证据清单；退出1先修评估脚本。任何一种都不能被 `|| true` 或忽略返回码变成完成结论。最终必须检查报告与decision一致，真实成果包可读，全部实测值可回到明细。
